# 017 제외한 가게도 포함해서 돌리기

## 지시 (PM)
- 배경(2026-11-05 사용자 결정): 016에서 제외 되돌리기·목록 화면을 만들지 않았다. 그 대신 **이번 한 번은 제외한 가게까지 넣고 돌리는** 선택지를 둔다. 제외 기록 자체는 건드리지 않는다(지우지도, 기간을 늘리지도 않음).

### 동작 (사용자가 정한 것)
1. 돌리기 버튼 **왼쪽에 체크박스**를 둔다. 돌리기 버튼은 지금처럼 줄을 꽉 채우지 말고 좌우를 조금 줄여, 같은 줄에 `[☐ 라벨] [🎰 돌리기]`로 놓는다.
2. 기본값은 **체크 해제**. 상태를 **저장하지 않는다**(localStorage 등 X). 새로고침하면 다시 해제.
3. 체크하면 다음 돌리기부터 제외 빼기 단계를 건너뛰고 기존 조건(지역·그룹·업종·오늘 휴무) 후보 전체에서 뽑는다.

### 구현 기준 (PM 판단, 재량 범위)
- 라벨 문구: **`제외 포함`**. 체크박스와 라벨 전체가 눌리는 영역(`<label>`로 감싸기), 터치 높이 40px 이상. 접근성 이름은 `제외한 가게도 포함해서 돌리기` 정도로 풀어서(`aria-label` 또는 `title`).
- 줄 배치: 체크박스 묶음은 내용 폭만큼, 돌리기 버튼이 나머지 폭(flex:1). 돌리기 버튼 높이·글자 크기는 지금 그대로. 360px에서 한 줄 유지, 라벨이 줄바꿈되거나 버튼 글자(`🎰 다시 돌리기` 포함)가 넘치면 안 된다. 체크박스 색은 테마 강조색(`accent-color: var(--accent)`) — 6개 테마 라이트·다크 모두에서 보이는지 확인.
- 체크박스는 돌리기 버튼과 같이 비활성화된다(지역 미선택·돌리는 중). 돌리는 중에 바꿀 수 없게.
- 체크 상태에서는 016의 대체 안내(`제외한 가게뿐이라 이번엔 전체에서 뽑았어요`)가 **나오지 않는다**(애초에 빼지 않았으므로).
- 체크 상태로 뽑힌 카드가 제외된 가게면, 그 카드의 제외 버튼은 지금처럼 처음부터 `제외됨`·비활성(기존 동작 유지 확인만).
- 체크를 바꿔도 현재 결과 화면은 그대로(다음 돌리기부터 적용). 모드 전환·지역 변경 때 체크를 초기화할 필요 없음(새로고침 때만 해제).
- 순수 로직은 `js/exclude.js`에서 처리하고 테스트를 추가한다. 예: `withoutExcluded(candidates, excluded, keyOf, { include: true })` → `{ list: candidates, fallback: false }`. 이름·형태는 재량.
- `APP_VERSION`은 바꾸지 않는다(사용자가 릴리스 때 정함). `npm run bump`는 실행.
- README 기능 소개의 제외 설명에 한 줄 덧붙이고 테스트 수 갱신.
- 범위: `js/exclude.js`·`js/app.js`, `index.html`, `css/style.css`, `tests/exclude.test.js`, README, 버전 bump. 의존성 추가·커밋 금지. 화면 확인은 저장소 밖 복사본 + 가짜 CSV.
- 계획과 다르게 해야 할 이유가 생기면 임의로 바꾸지 말고 보고에 질문으로 남기고 멈춘다.
