### 목표
README가 v2.3 시점의 "백엔드 없음" 이야기에 머물러 있다. v2.4~v2.5에서 추가된 것을 README에 반영한다. 추가된 것은 선택형 추천 서버, AI 메뉴 추천, 공지 팝업, AI 추천 피드백이다. 기존 README의 톤(해요체, "왜 → 어떻게 → 고민"의 흐름)과 구성은 유지한다.

### 고칠 곳
1. **상단 소개·배지**
   - `Backend-없음` 배지는 이제 사실과 다르다. "사이트는 백엔드 없이 동작하고, AI 추천만 선택형 서버를 쓴다"는 뜻이 드러나게 바꾼다. 예: `Backend-선택(AI 추천)`. 문구는 판단해도 된다.
   - 소개 두 줄 아래에 AI 메뉴 추천을 한 줄 더한다(예: "켜두면 AI가 오늘 날씨에 어울리는 업종을 골라줘요").
   - `dependencies-0`은 유지한다(서버도 외부 패키지 없음).
2. **✨ 주요 기능**
   - `🤖 AI 메뉴 추천` 행을 v2.5 기준으로 고친다. 담을 내용은 다음과 같다.
     - 제목 아래 `추천` 줄의 켜기·끄기, 처음엔 꺼짐
     - AI가 지역별 점심시간 날씨를 보고 업종 2~6개와 한 줄 문구를 고름(날마다 조금씩 달라짐, 무난한 날도 추천)
     - AI가 실패하면 날씨 규칙으로 대신 추천, 작은 글씨로 출처 구분
     - 꺼져 있어도 비·더위·추위인 날엔 날씨 배지
     - 업종은 언제든 직접 바꿀 수 있음
   - `📣 공지 · AI 추천 피드백` 행을 실제 동작에 맞게 고친다.
     - 공지: 시트에서 관리, 여러 개면 차례로, 오늘 하루 안 보기·다시 띄우지 않기
     - 피드백: AI 추천 첫 결과 때 한 번, 이후 하단 버튼
3. **📸 화면**: 새 스크린샷 표를 하나 더한다(아래 "스크린샷").
4. **⚙️ 어떻게 동작하나요**
   - "서버가 하나도 없어요"를 고친다. 기본 기능은 지금처럼 서버 없이 돌고, AI 추천만 선택형 서버를 쓴다는 점을 쓴다. 서버 구성은 사용자 리눅스 서버의 Docker, Node 22, 외부 패키지 없음, Open-Meteo 날씨, Claude Code CLI다.
   - mermaid 그림에 세 가지를 더한다. 하나는 추천 서버(Open-Meteo → 날씨 판정, 시트 CSV → 업종 목록, Claude CLI → 업종·문구 선택, 메모리 캐시)와 브라우저의 `GET /recommend` 흐름이다. 다른 둘은 `공지관리` 탭 → 공지 팝업, 피드백 → Google Form이다. 그림이 너무 커지면 서버 쪽을 별도 작은 그림으로 나눠도 된다.
5. **🧠 고민했던 것들**: `<details>` 항목을 세 개 더한다. 사실은 설계서·인계서에서 가져오고, 지어내지 않는다.
   - **"AI 추천"이 정말 AI가 고르게 하려면** (v2.4 → v2.5)
     - v2.4는 AI가 업종 성격 분류만 하고 날씨 → 업종은 규칙이었다. 그래서 사실상 규칙 기반이라는 지적을 받았다.
     - v2.5에서는 AI가 업종과 문구를 직접 고른다. 날마다 조금씩 다른 결과를 일부러 허용했고, 규칙은 실패 대비와 정반대 업종 제외(비·추운 날 냉메밀, 더운 날 국물)에만 쓴다.
   - **AI를 언제, 몇 번 부를까**
     - 기기마다가 아니라 서버 기준으로 지역·날짜·날씨 분류가 바뀔 때만 부른다. 같은 날 같은 지역이면 모두 같은 추천을 본다.
     - API 키 대신 서버에 로그인한 Claude Code CLI를 쓴다.
     - 응답은 AI를 기다리지 않는다. 결과가 없으면 규칙으로 바로 답하고 AI는 뒤에서 돈다. 이렇게 해서 3초 제한을 지킨다.
     - 실패하면 30분 뒤 다시 시도하고, 하루 3회까지만 시도한다.
     - 시트의 업종 이름이 프롬프트에 들어가므로 이름만 넘기고, 도구를 끄고, 출력은 목록 대조와 길이 제한을 거친다.
   - **공지를 관리자 화면 없이 띄우려면**
     - 서버에 관리자 화면·인증을 만드는 대신 구글 시트 `공지관리` 탭을 관리자 화면으로 썼다.
     - 체크박스로 켜고 끄고, 기간을 지정하고, 내용은 글자로만 표시한다.
   - 기존 "백엔드 없이 동료들의 평가를 모으려면?" 항목 끝에 한 줄을 더한다. 피드백 폼이 로그인 응답자만 받도록 설정돼 있어서, 사이트는 성공처럼 보였는데 응답이 쌓이지 않았던 일이 있었다. 그래서 폼 응답자 범위를 꼭 확인해야 한다(`docs/SETUP.md` 링크).
6. **🛠️ 기술 스택**: "AI 추천 서버" 행을 더한다. Node 22 `node:http`(외부 패키지 없음), Open-Meteo, Claude Code CLI(`claude -p`), Docker다.
7. **📁 구조**: `js/recommend.js`, `js/notice.js`, `js/feedback.js`, `js/dialogs.js`와 `server/`(주요 파일 한 줄씩: `index.js`, `app.js`, `weather.js`, `sheet.js`, `rules.js`, `tags.js`, `recommender.js`, `pick-jobs.js`, `classifier.js`, `Dockerfile`, `compose.example.yml`, `data/category-tags.json`)를 더한다. 테스트 개수는 실제 `npm test` 결과로 쓴다.
8. **🚀 직접 써보기**: 추천 서버는 선택이라는 점, 공지·피드백 설정도 SETUP에 있다는 점을 한 줄 더한다.

  - `ai-recommend.png`: 점심 모드, AI 추천 켜짐, 안내 문구와 `🤖 AI 추천 · … 갱신` 작은 글씨, 자동으로 켜진 업종 칩이 보이는 화면(라이트).
  - `ai-badge-off.png`(선택): 추천 꺼짐 + 날씨 배지. 오늘 실제 날씨가 무난하면 배지가 안 나오므로 가짜 응답으로 찍는다.
  - `notice.png`: 공지 팝업(라이트 또는 다크 중 하나).
  - `feedback.png`: 피드백 모달에서 별을 골라 문구(`좋아요` 등)가 보이는 상태.

- **금지**: 실제 구글 폼 전송. 피드백·별점 전송 요청은 반드시 가로채서 막는다(`docs.google.com/forms/.../formResponse`). 운영 시트를 고치지 않는다.
- README에서 이미지는 기존처럼 `<table>`과 `width`로 넣고, `alt`는 화면 내용을 구체적으로 쓴다.
