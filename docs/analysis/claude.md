# lunch-selector 진단 — 클로드

## 분석 방법

- 읽은 파일: `js/*.js` 9개 전부, `index.html`, `css/style.css`(관련 구간), `tests/*.test.js`(map·select 중심), `data/sample-stores.csv`, `README.md`, `docs/SETUP.md`, `docs/superpowers/specs/2026-10-19-lunch-selector-design.md`, `git log`
- 실행: `npm test` → **59개 전부 통과** (약 150ms). `node -e`로 `isEnabled`·`parseDays` 엣지 값 직접 확인(결과는 S-02, S-05에 인용).
- 브라우저 실행·실제 시트 접속은 하지 않았다. 화면·지도 동작은 코드만 읽고 판단했다.
- 대략 20분.

전체 인상: 순수 로직(CSV·정규화·선택)은 함수로 잘 분리되어 있고 테스트도 촘촘하다. XSS도 깔끔하게 막혀 있다(모든 출력이 `textContent`, 링크는 `encodeURIComponent`). 약한 곳은 **테스트가 없는 `app.js`(351줄, 가장 큰 파일)**, **문서와 실제 설정의 어긋남**, **네트워크 실패 시 처리**다.

## 요약

1. **S-01** 시트 요청에 타임아웃이 없다. 구글 응답이 멈추면 "불러오는 중..."에서 영원히 멈추고, 다시 시도 버튼도 안 나온다.
2. **S-03** `SETUP.md`가 실제 설정과 다르다(탭 이름 `가게목록`, "새로고침만 하면 반영"). 시트를 고치는 사람이 헷갈린다.
3. **E-01** `pickTop`이 이미 `rng`를 주입받는다. 날짜+그룹 시드로 바꾸면 백엔드 없이 **같은 그룹 모두가 같은 결과**를 본다(F-01).
4. **S-04** 화면 로직 전체(`app.js`)에 테스트가 없다. 기능을 늘릴수록 회귀 위험이 이곳에 몰린다.
5. **E-04** CI가 없고 Pages가 `main`을 그대로 배포한다. 테스트가 깨진 커밋도 바로 실서비스에 나간다.

## 1. 소스 개선점

### S-01 시트 요청에 타임아웃이 없음
- 위치: `js/data.js:15`, `js/app.js:281-295`
- 내용: `fetch`에 `signal`이 없다. 응답이 오지 않으면 Promise가 끝나지 않는다.
- 근거: `load()`는 `try/catch`만으로 실패를 다룬다. 끝나지 않는 요청은 catch에 도달하지 않아, `els.retry.hidden = false`가 실행되지 않는다. 그래서 메시지는 "불러오는 중..."에 고정되고 돌리기 버튼도 비활성 상태로 남는다.
- 영향: 사내망·모바일 불안정 환경에서 새로고침 말고는 빠져나갈 방법이 없다.
- 제안: `loadStores(url, fetchFn, { timeout = 10000 })`에서 `AbortSignal.timeout(timeout)`을 넘긴다. 타임아웃도 기존 실패 경로(재시도 버튼)를 타게 한다. `fetchFn`이 이미 주입식이라 테스트하기 쉽다.
- 확신도: 높음
- 규모: S

### S-02 `사용여부`의 "아니요"가 사용으로 처리됨
- 위치: `js/stores.js:6`
- 내용: 끄는 값 목록이 `['false', 'n', '아니오', '0']`이다. 표준 표기 "아니요"와 `no`, `x`, `미사용`은 모두 **사용**으로 처리된다.
- 근거: `isEnabled('아니요')`, `isEnabled('no')`, `isEnabled('x')`, `isEnabled('미사용')` → 모두 `true` (직접 실행).
- 영향: 체크박스 대신 글자로 적는 사람이 "아니요"를 쓰면 빼려던 가게가 계속 뽑힌다. 이는 스펙의 안티목표("시트 입력이 조금 어긋났다고 … 깨짐")에 해당한다.
- 제안: `아니요`, `no`, `x`, `미사용`, `off`를 목록에 추가하고 테스트도 함께 넣는다.
- 확신도: 높음
- 규모: S

### S-03 운영 문서가 실제 설정과 어긋남
- 위치: `docs/SETUP.md` "만들기"·"연결" 절, `js/config.js:10-21`
- 내용:
  - SETUP은 탭 이름을 `가게목록`이라고 안내한다. 실제 설정은 `점심메뉴`, `다과(커피)메뉴`다.
  - SETUP은 "시트를 고치면 새로고침만 하면 반영된다"고 한다. 그런데 현재 설정은 `PUBLISH_URL`을 쓰는 **게시 방식**이고, 같은 문서의 "대안" 절에 따르면 이 방식은 반영에 **최대 5분**이 걸린다.
  - "대안: 웹에 게시"는 시트를 공개 공유하고 싶지 않을 때 쓰는 방법으로 설명되어 있다. 그런데 `SHEET_ID`도 함께 채워져 있어서 편집 링크가 노출된다.
- 근거: 위 파일 대조.
- 영향: 시트를 고친 사람이 "반영이 안 된다"며 여러 번 새로고침하거나 탭 이름을 바꿔 버릴 수 있다. 탭 이름 변경은 gviz로 되돌렸을 때 바로 깨진다.
- 제안: SETUP을 현재 운영 방식(게시 + 편집 링크) 기준으로 다시 쓰고, gviz는 대안으로 내린다. 지연 안내 문구를 사이트 푸터 편집 링크 옆에도 넣는 것을 검토한다.
- 확신도: 높음
- 규모: S

### S-04 `app.js`에 테스트가 없고 상태·DOM·흐름이 한 파일에 섞여 있음
- 위치: `js/app.js` 전체
- 내용: 모드/그룹/업종 선택, 저장소 복원, 로딩 경쟁 상태(`mode !== state.mode`), 결과 회차(`state.round`) 가드가 모두 이 파일에 있다. 모두 테스트가 없다. 이 중 경쟁 상태 처리는 잘 짜여 있지만 회귀를 잡아줄 장치가 없다.
- 근거: `tests/`에 `app` 관련 파일이 없다. 최근 커밋(`625d037` 테마, `59bc57f` 모드 전환, `cff3013` 지도)이 모두 `app.js`를 고쳤다.
- 영향: 기능을 붙일 때마다 이 파일이 커진다. "모드 전환 중 실패", "돌리는 중 그룹 변경" 같은 시나리오를 매번 손으로 확인해야 한다.
- 제안: (1) 초기 선택 결정처럼 DOM 없는 판단을 순수 함수로 뺀다. 예: `initialGroup(saved, groups)`(`app.js:306-307`)를 `select.js` 쪽으로. (2) 이어서 `state` 전이(`selectGroup`·`selectMode`·`spin` 가드)를 DOM과 분리한 작은 스토어로 바꾼다. 의존성 0 원칙을 지키려면 jsdom 대신 이 방식이 맞다.
- 확신도: 중간 (방향은 확실하고, 어디까지 분리할지는 취향)
- 규모: M

### S-05 정기휴무 칸의 흔한 표현이 경고만 남기고 무시됨
- 위치: `js/stores.js:34-46`
- 내용: `없음`, `연중무휴`, `공휴일`, `매주 월`의 `매주`는 경고와 함께 버려진다. `일요일,공휴일`은 일요일만 인식된다.
- 근거: `parseDays('연중무휴')` → `[]` + 경고, `parseDays('매주 월')` → `[1]` + "매주" 경고 (직접 실행).
- 영향: 결과는 대체로 의도와 맞는다(휴무 없음 = 빈 배열). 다만 콘솔 경고가 쌓여 진짜 오타를 가린다. `공휴일`을 적은 사람은 공휴일에 제외될 거라 기대하는데 실제로는 안 빠진다.
- 제안: `없음|연중무휴|무휴`는 경고 없이 빈 값으로, `매주`는 무시어로 처리한다. `공휴일`은 비목표(비정형 휴무)라 처리하지 않되, 화면 어딘가에 "인식 못 한 휴무 값" 개수를 보여 주면 시트 관리자가 알아챌 수 있다.
- 확신도: 중간
- 규모: S

### S-06 `cachedLookup` 주석과 실제 동작이 다름
- 위치: `js/map.js:20`, `js/map.js:90-96`
- 내용: 주석은 "실패는 null이고 캐시하지 않는다"라고 한다. 그런데 `geocode`는 주소를 못 찾았을 때 throw하지 않고 `null`을 **resolve**한다. 그래서 "못 찾음"은 캐시된다. 캐시되지 않는 것은 예외(SDK 로드 실패 등)뿐이다.
- 근거: 테스트 `cachedLookup: 조회가 실패하면 … 다시 묻는다`는 throw 경우만 확인한다.
- 영향: 동작 자체는 합리적이다(틀린 주소를 반복 조회하지 않음). 다만 다음 사람이 주석을 믿고 고치면 헷갈린다.
- 제안: 주석을 "예외는 캐시하지 않고, 못 찾은 결과(null)는 캐시한다"로 고치고, 그 경우의 테스트를 하나 추가한다.
- 확신도: 높음
- 규모: S

### S-07 SDK 타임아웃 뒤 늦게 로드되면 스크립트가 중복 삽입될 수 있음
- 위치: `js/map.js:54-73`
- 내용: 8초 타임아웃으로 reject되면 `sdk = null`이 된다. 하지만 이미 넣은 `<script>`는 계속 로드된다. 다음 돌리기에서 `loadSdk`가 **두 번째 script**를 붙이고, 늦게 도착한 첫 스크립트와 둘째가 모두 `kakao` 전역을 초기화한다.
- 근거: reject 경로에서 `script.remove()`나 `window.kakao` 존재 확인을 하지 않는다.
- 영향: 느린 망에서 드물게 생긴다. 지도가 깨지거나 콘솔 에러가 날 수 있다.
- 제안: `loadSdk` 앞에서 `window.kakao?.maps`가 있으면 `maps.load`만 호출한다. 타임아웃 시 script 요소를 제거한다.
- 확신도: 중간 (실제 재현은 안 해 봄)
- 규모: S

### S-08 빈 결과 안내 문구가 원인을 구분하지 않음
- 위치: `js/app.js:299-304`
- 내용: 가게는 있지만 모두 `사용여부` FALSE이거나 그룹이 비어 있어도 "시트에 가게가 없어요"라고 나온다.
- 영향: 시트 관리자가 원인을 못 찾는다. 콘솔 경고는 일반 사용자에게 안 보인다.
- 제안: `stores.length`와 그룹 유무로 문구를 나눈다("모든 가게가 꺼져 있거나 그룹이 비어 있어요").
- 확신도: 높음
- 규모: S

### S-09 (경미) 기타
- `js/app.js:351` — `modes()`가 비면(설정 실수) `undefined.id`에서 전체가 죽는다. 이때는 안내 문구를 띄운다.
- `js/app.js:12` — `'*'`를 "전체" 저장값으로 쓴다. 그룹 이름이 `*`이면 충돌한다(현실성은 낮음).
- `index.html:43-46` — 2·3순위 카드는 릴이 도는 동안 `opacity: 0`일 뿐 DOM에 내용이 있다. 그래서 화면 낭독기로 탐색하면 결과가 미리 읽힌다. `fillRank`를 공개 시점으로 옮기거나 `aria-hidden`을 토글하면 된다.
- 확신도: 높음 / 규모: S

## 2. 확장 가능성

### E-01 추천 방식은 이미 교체 가능한 구조
- 위치: `js/select.js:68` (`pickTop(candidates, count, rng)`)
- 내용: 난수원이 주입식이다. 시드 난수(날짜+그룹+모드 해시)를 넣으면 **서버 없이도 같은 날 같은 그룹은 같은 결과**가 나온다. 가중치(예: `가중치` 열)도 이 함수 하나만 바꾸면 된다.
- 막히는 곳: "누가 이미 돌렸는지", "투표" 같은 공유 상태는 정적 사이트로는 불가능하다.
- 확신도: 높음 / 규모: S

### E-02 열 추가는 쉽지만 코드 두 곳을 고쳐야 함
- 위치: `js/stores.js:3`(typedef), `js/stores.js:8-16`(`HEADERS`), `js/stores.js:73-81`
- 내용: 헤더 이름으로 열을 찾으니 시트 쪽 확장은 자유롭다. 반면 새 열을 **쓰려면** 매핑·정규화 코드를 손대야 한다.
- 제안: 확장이 잦아지면 `HEADERS`를 `{ key, label, parse }` 배열로 바꿔 열 정의를 한 곳에 모은다. 지금 규모에서는 굳이 하지 않아도 된다.
- 확신도: 중간 / 규모: S

### E-03 지오코딩을 매번 다시 하지 않도록 할 여지
- 위치: `js/map.js:20-34`, `js/app.js:195`
- 내용: 좌표 캐시가 메모리에만 있어서, 새로고침할 때마다 다시 조회한다. 선택지는 둘이다. (a) `localStorage`에 주소→좌표를 저장한다. (b) 시트에 `좌표` 열을 두고, 있으면 지오코딩을 건너뛴다. (b)는 "못 찾는 주소"를 사람이 직접 고칠 수 있는 탈출구도 된다(`coreAddress` 휴리스틱의 한계 보완).
- 확신도: 높음 / 규모: S~M

### E-04 배포 전 검증 단계가 없음
- 위치: 저장소 루트 (`.github/` 없음), `docs/SETUP.md` "GitHub Pages 배포"
- 내용: `main` 브랜치 루트를 그대로 Pages로 서빙한다. 테스트는 사람이 손으로 돌린다.
- 제안: GitHub Actions에 `npm test` → `actions/deploy-pages` 흐름을 만든다(테스트 실패 시 배포 중단). Gitea(backup 원격)에도 Colossus처럼 act_runner가 있으니 같은 워크플로우를 재활용할 수 있다.
- 확신도: 높음 / 규모: S

### E-05 데이터 소스 다중화의 한계선
- 내용: 모드 = 시트 탭 하나다. 탭 추가는 `MODES` 한 줄이면 되고(잘 설계됨), 같은 원리로 회사·건물마다 다른 시트를 쓰는 것도 `config.js` 교체로 된다. 다만 **URL 쿼리로 시트를 바꾸는 기능**을 넣는 순간 남의 시트를 띄우는 피싱 수단이 될 수 있다. 쿼리로는 모드·그룹만 지정하는 게 안전하다(F-03).
- 확신도: 중간 / 규모: —

### E-06 오프라인·실패 대비
- 내용: 마지막으로 성공한 CSV를 `localStorage`에 저장해 두면, 시트 접속에 실패해도 "어제 목록으로 고르기"가 가능하다. 구조상 `loadStores`만 감싸면 되어 다른 모듈에 영향이 없다. 나중에 PWA(서비스 워커)로 넘어갈 수도 있지만, 지금 쓰임새에는 과하다.
- 확신도: 높음 / 규모: S

## 3. 추가 기능 후보

> 스펙의 비목표(방문 이력, 임시 휴무, 투표, 효과음)와 부딪히는 항목은 따로 표시했다.

### F-01 "오늘의 결과" 고정 (그룹 전원이 같은 결과)
- 사용 장면: 3층 사람들이 각자 휴대폰으로 돌리면 결과가 다 달라서, 누구 결과를 따를지 또 정해야 한다.
- 구현 개요: 시드 난수를 쓴다(E-01). "오늘의 추천" 모드는 날짜+그룹 시드로, "다시 돌리기"는 지금처럼 무작위로.
- 현 구조와의 궁합: 매우 좋음 (서버 불필요, `pickTop` 그대로)
- 확신도: 높음 / 규모: S

### F-02 결과 공유 (메신저로 보내기)
- 사용 장면: 결과를 팀 단톡방이나 메신저에 올린다.
- 구현 개요: `navigator.share` → 없으면 클립보드 복사. 문구 예: "오늘 점심 1순위 ○○ / 2순위 … + 카카오맵 링크".
- 궁합: 좋음 / 확신도: 높음 / 규모: S

### F-03 링크로 모드·그룹 지정 (`?mode=cafe&group=3층`)
- 사용 장면: 층별 공지나 북마크로 "우리 층 화면"을 바로 연다. 현재는 `localStorage` 기억에만 기대서 기기를 바꾸면 처음부터 다시 골라야 한다.
- 구현 개요: 초기 선택 시 쿼리 > 저장값 > 첫 그룹 순으로 정한다. 시트 주소는 쿼리로 받지 않는다(E-05).
- 궁합: 좋음 / 확신도: 높음 / 규모: S

### F-04 "이건 빼고 다시" (거부권)
- 사용 장면: 1순위가 어제 간 곳이라 빼고 다시 돌리고 싶다. 지금은 다시 돌리면 같은 곳이 또 나올 수 있다.
- 구현 개요: 카드에 ✕ 버튼 → 그날(세션) 동안 후보에서 제외. 날짜가 바뀌면 초기화.
- 궁합: 좋음. 다만 **비목표 "최근 방문 이력"과 경계**에 있다. 세션 한정이면 비목표를 침범하지 않는다고 본다.
- 확신도: 중간 / 규모: S

### F-05 거리·도보 시간 / 가격대 열
- 사용 장면: 비 오는 날 가까운 곳만, 월말에 싼 곳만.
- 구현 개요: 시트에 `도보(분)`, `가격대` 열을 추가하고 기존 업종 칩처럼 필터 칩으로 만든다. 거리는 회사 좌표가 있으면 지오코딩 좌표로 자동 계산할 수도 있다(E-03).
- 궁합: 보통 (E-02 열 추가 비용) / 확신도: 중간 / 규모: M

### F-06 임시 휴무 날짜 열 — *비목표와 충돌*
- 사용 장면: 사장님 휴가 공지를 본 사람이 시트에 `휴무일: 11/5~11/7`을 적는다.
- 구현 개요: 날짜 범위를 파싱해 `filterCandidates`의 `day` 조건 옆에 `date` 조건을 추가한다.
- 궁합: 좋음. 다만 스펙이 명시적으로 "2·3순위로 대응"하기로 했으므로, 다시 열지는 사용자 판단이 필요하다.
- 확신도: 중간 / 규모: S~M

### F-07 영업시간 / 브레이크타임 — *비목표 아님, 보류 권장*
- 사용 장면: 1시 넘어 늦은 점심일 때 브레이크타임인 곳이 뽑힌다.
- 구현 개요: `영업시간` 열 파싱 + 현재 시각 비교.
- 궁합: 시트 입력 형식이 자유로워 파싱 실패가 잦을 것이다(S-05와 같은 문제). 실제 수요가 확인될 때까지 보류를 권한다.
- 확신도: 낮음 / 규모: M

## 판단 보류 · 질문

1. **시트 공개 범위**: 지금은 게시 방식(`PUBLISH_URL`)과 편집 링크(`SHEET_ID`)를 둘 다 쓴다. 시트가 아직 "링크가 있는 모든 사용자 – 편집자"인가? 아니라면 편집 링크는 권한 요청 화면으로 이어진다. 의도대로인지 확인이 필요하다(S-03).
2. **비목표 재검토 여부**: F-04(세션 거부권)와 F-06(임시 휴무 날짜)은 원래 스펙이 비목표로 정한 영역과 맞닿아 있다. 실제로 써 보니 필요했는지가 우선순위를 가른다.
3. **"같은 그룹 같은 결과"(F-01)를 원하는지**: 지금처럼 각자 돌리는 재미가 더 중요할 수도 있다.
