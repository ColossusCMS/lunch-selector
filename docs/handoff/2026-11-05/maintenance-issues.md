- 재현 표시: **재현함**은 복사본에서 실제로 돌려 확인했다는 뜻이고, **코드 확인**은 코드를 읽고 판단했지만 실행해 보지는 않았다는 뜻이다.

## 목표 / 범위
아래 7건을 고친다. 하지 말 것은 다음과 같다.
- 연출(`js/reveal.js`, `js/reveal-plan.js`)과 기능 동작은 바꾸지 않는다.
- `js/config.js`의 운영 값은 바꾸지 않는다.
- **실제 구글 폼으로 전송하지 않는다.** 실제 시트와 폼은 사용자들이 쓰는 운영 데이터다. 화면 확인은 가짜 CSV와 가짜 폼 주소로 한다.
- 런타임 의존성을 추가하지 않는다. 백엔드·빌드 없음이 이 프로젝트의 핵심 제약이다.

## H-1 시트에 같은 가게가 두 행이면 추첨이 왜곡된다 (중) — 재현함
- 위치: `js/stores.js`의 `rowsToStores`, `js/select.js`의 `pickTop`
- 현상: 같은 지역에 같은 가게명이 두 행이면 별개 가게로 뽑힌다. `김밥, 김밥, 국밥, 냉면` 4행으로 10만 회 돌리면 김밥이 1순위로 50.2% 나오고(기대 33%), 1·2·3순위에 같은 가게가 겹치는 경우가 50.4%다.
- 기대 동작: 같은 지역·같은 가게명은 한 가게로 뽑힌다.
- 제안: 정규화 단계에서 `지역 + 가게명`으로 합친다. 그룹을 행마다 나눠 적었을 수 있으므로 첫 행만 남기지 말고 `groups`·`categories`는 합집합으로 만들고 `console.warn`을 남긴다. 다른 열이 충돌하면 첫 행 값을 쓴다.
- 먼저 볼 것: 운영 시트에 실제로 중복 행이 있는지 확인한다.

## H-2 `npm run bump`를 빼먹어도 테스트가 통과한다 (중) — 재현함
- 위치: `tests/version.test.js`, `scripts/bump-version.mjs`
- 현상: 테스트는 모든 참조의 `?v=` 값이 서로 같은지만 본다. `js/exclude.js`를 고치고 bump 없이 돌려도 통과한다.
- 영향: 배포 후 브라우저 캐시로 새 파일과 옛 파일이 섞일 수 있다. 사이클 005에서 화면이 멈춘 사고의 재발 경로다.
- 제안: 시각 대신 콘텐츠 해시를 버전으로 쓴다. bump가 `css/*`와 `js/*`에서 `?v=…`를 뺀 내용으로 해시를 만들고, 테스트가 같은 방식으로 다시 계산해 비교하면 bump를 빼먹은 커밋은 테스트에서 실패한다. `tests/version.test.js`의 `\?v=\d{12}` 형식 검사도 함께 바꾼다.

## H-4 시트 공유 설명이 서로 충돌한다 (확인 필요) — 코드 확인, 실제 설정은 미확인
- 위치: `docs/SETUP.md:37`, `README.md:166`
- 현상: SETUP은 "링크가 있는 모든 사용자 / 편집자"를 안내하고, README는 공유 범위를 좁게 유지한다고 설명한다.
- 영향: `SHEET_ID`는 `js/config.js`와 화면의 편집 링크로 공개돼 있다. 실제 시트가 링크 편집 허용이면 주소를 아는 누구나 가게 목록을 고칠 수 있다.
- 할 일: 운영 시트의 일반 액세스 설정을 확인하고 의도를 정한 뒤 두 문서를 맞춘다. 동료가 편집하게 하려면 지금 설정의 위험을 받아들이거나 편집자를 지정해야 한다. 함께 볼 것: SETUP은 평점 탭만 게시한다고 안내하고 README는 전체 문서 게시를 설명한다.

## H-5 페이지 로드 때만 평가 창과 데이터를 확인한다 (중하) — 코드 확인, 실기기 미확인
- 위치: `js/app.js`의 `initRatings`, `load`, `storeCache`
- 현상: `visibilitychange`·`pageshow` 처리가 없다. 휴대폰에서 탭을 살려 둔 채 돌아오면 30분이 지나도 평가 창이 뜨지 않고, 가게 목록과 평점도 그대로일 수 있다.
- 제안: 화면이 다시 보일 때 평가 조건을 재확인한다. 돌리는 중이나 다른 창이 열려 있을 때는 건너뛴다. 목록은 일정 시간이 지난 경우에만 다시 받는다.
- 먼저 볼 것: 실제 휴대폰에서 재현되는지 확인하고, 재현되지 않으면 닫는다.
