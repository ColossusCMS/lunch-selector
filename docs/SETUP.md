# 설치·운영 가이드

직접 띄우거나 시트를 연결할 때 보는 문서입니다. 프로젝트 소개는 [README](../README.md)에 있어요.

## 사용법

0. 맨 위 **[🍱 점심] [☕ 카페]**로 고를 목록을 바꿉니다. (탭이 하나뿐이면 이 버튼은 숨겨져요.)
1. 지역이 여러 개면 먼저 지역을 고릅니다. 이어 그룹을 고르거나 **[전체]**로 그 지역의 모든 가게를 봅니다. 그룹 없는 지역은 그룹 줄이 숨겨져요. 지역과 지역별 마지막 그룹을 브라우저가 기억해요.
2. 필요하면 업종 버튼을 켭니다. 여러 개를 켜면 하나라도 해당하는 가게가 후보이고, **[전체]**를 누르면 업종 선택이 모두 풀려요.
3. **🎰 돌리기**를 누르면 1순위가 뽑히고, 2·3순위가 차례로 나타납니다. 주소가 적힌 가게는 아래 지도에 순위 핀으로 표시돼요.
4. 1순위가 내키지 않거나 임시 휴무라면 2순위, 3순위로 가면 돼요.

## 가게 목록 시트

### 만들기

- 탭 이름: `가게목록`
- **헤더 첫 셀은 반드시 `A1`**이고, 1행에 한 줄로 적습니다. 데이터는 2행부터.
- 열 순서는 자유. 아래에 없는 열(예: 전화번호)은 무시됩니다.
- 셀 병합, 2줄 헤더는 쓰지 마세요.

| 열 | 필수 | 적는 법 | 예 |
|---|---|---|---|
| `가게명` | 필수 | 비어 있으면 그 행은 건너뜀 | 김밥천국 |
| `업종` | | 쉼표로 여러 개 | `분식,한식` |
| `지역` | | 값 하나. 열 없음/모두 빈칸이면 기존 방식. 일부만 빈칸이면 해당 행 제외. 쉼표가 있으면 첫 값만 사용 | `검암` |
| `그룹` | | 쉼표로 여러 개. 빈칸은 해당 지역의 [전체]에서만 나옴 | `3층,4층` |
| `정기휴무` | | 요일 한 글자를 쉼표로 (`월요일`도 인식) | `토,일` |
| `혼잡도` | | `여유`, `보통`, `혼잡`만 표시. 빈칸/다른 값은 미표시. 추첨 확률에는 영향 없음 | `혼잡` |
| `메모` | | 결과 카드에 작게 표시 | 짬뽕 맛집 |
| `주소` | | 도로명·지번 주소. 지도 핀과 "📍 카카오맵" 링크에 쓰임. 비우면 지도에서만 빠짐 | 서울 중구 세종대로 110 |

예시는 [`data/sample-stores.csv`](../data/sample-stores.csv)를 참고하세요.

### 공유

시트의 **공유 → 일반 액세스: 링크가 있는 모든 사용자 / 편집자**. 사이트의 "✏️ 가게 목록 편집하기" 링크로 누구나 시트를 고칠 수 있어요. 실수로 지웠다면 **파일 → 버전 기록**으로 되돌리면 됩니다.

### 연결

[`js/config.js`](../js/config.js)에서:

```js
export const SHEET_ID = '...';     // 시트 주소의 /d/ 와 /edit 사이 값 (편집 링크용)
export const PUBLISH_URL = '...';  // "웹에 게시" 주소에서 /pub 까지. 비우면 SHEET_ID로 gviz 방식
export const MODES = [             // 상단 전환 버튼 = 시트 탭
  { id: 'lunch', label: '🍱 점심', heading: '🍱 오늘 점심 뭐 먹지?', tab: '점심메뉴', gid: '0' },
  { id: 'cafe',  label: '☕ 카페', heading: '☕ 오늘 카페 어디 가지?', tab: '다과(커피)메뉴', gid: '611891333' },
];
```

- 탭마다 열 구성은 같습니다. 탭을 하나 더 쓰려면 `MODES`에 한 줄 추가하세요.
- `gid`는 그 탭을 열었을 때 주소창 끝 `#gid=` 숫자, `tab`은 탭 이름입니다. 게시 방식은 `gid`, gviz 방식은 `tab`을 쓰고, 그 값이 빈 모드는 버튼에서 빠집니다.
- 시트를 고치면 새로고침만 하면 반영됩니다.

### 지도 (카카오맵)

[`js/config.js`](../js/config.js)의 `KAKAO_MAP_KEY`에 카카오 **JavaScript 키**를 넣으면 켜지고, 비우면 꺼집니다.

1. [카카오디벨로퍼스](https://developers.kakao.com)에서 앱을 만들고 **[카카오맵] → 사용 설정 ON**.
2. **[앱] → [플랫폼 키] → [JavaScript 키] → [JavaScript SDK 도메인]**에 사이트 주소를 등록 (경로 없이 도메인까지만).
   - 배포: `https://<계정>.github.io`
   - 로컬: `http://localhost:5173` (등록한 포트로 띄워야 지도가 떠요: `npx serve -l 5173 .`)
3. 같은 화면의 JavaScript 키를 `KAKAO_MAP_KEY`에 넣습니다. 등록한 도메인에서만 동작하므로 공개돼도 괜찮아요.

주소를 못 찾거나 지도를 불러오지 못하면 지도만 숨고 추천은 그대로 동작합니다.

### 대안: 웹에 게시

시트를 공개 공유하고 싶지 않으면 **파일 → 공유 → 웹에 게시**에서 **전체 문서**를 **CSV**로 게시하고, 나온 주소의 `/pub` 까지를 `PUBLISH_URL`에 넣으세요. 이 방식은 반영까지 최대 5분 정도 걸릴 수 있어요. (편집 링크는 `SHEET_ID`가 있을 때만 보입니다.)

## 별점·좋아요 켜기

[`js/config.js`](../js/config.js)의 `RATING`을 모두 채우면 켜집니다. 하나라도 비어 있으면 평가 카드·배지·추천 기록 저장·평점 요청이 모두 꺼집니다. 지역 entry가 비어 있으면 꺼진 상태입니다.

1. 구글 폼을 만들고 질문 제목을 정확히 **`모드`, `지역`, `가게명`, `별점`, `좋아요`**로 만듭니다. 다섯 질문 모두 **단답형**, **필수 아님**으로 설정합니다. 익명으로 응답할 수 있도록 로그인 요구와 이메일 수집을 끕니다.
2. 폼의 **응답 → 스프레드시트에 연결 → 기존 스프레드시트 선택**으로 가게 목록 시트에 연결합니다. 새로 생긴 응답 탭 이름을 **`평점`**으로 바꿉니다.
3. `평점` 탭을 숨긴 다음, 시트의 **파일 → 공유 → 웹에 게시**에서 **평점 탭만**, 형식은 **CSV**로 선택합니다. 나온 전체 주소를 `RATING.csvUrl`에 넣습니다. 숨긴 탭이 게시되지 않으면 폼 응답을 새 스프레드시트로 연결하고 같은 방법으로 게시하세요.
4. 폼 미리보기 주소에서 끝의 `viewform`을 `formResponse`로 바꿔 `RATING.formUrl`에 넣습니다.
5. 폼의 **⋮ → 미리 채워진 링크 가져오기**에서 다섯 질문에 구별할 수 있는 값을 채우고 링크를 복사합니다. 주소의 `entry.NNN=값`에서 질문별 ID를 찾아 `RATING.entries`의 `mode`(모드), `region`(지역), `name`(가게명), `stars`(별점), `like`(좋아요)에 각각 넣습니다. 값은 `entry.123456`처럼 `entry.`까지 포함합니다.
6. 테스트 평가를 보내 응답 시트에 모드 id·지역·가게명·별점(`1`~`5` 또는 빈 값)·좋아요(`1` 또는 빈 값)가 들어오는지 확인합니다. 게시 CSV와 결과 배지에 반영되기까지 **몇 분 걸릴 수 있습니다**. 앱은 폼의 응답 내용을 확인할 수 없으므로 질문 ID가 맞는지도 시트에서 확인하세요.

평가 카드는 마지막 추천에서 30분이 지난 뒤 다음 접속 때 표시됩니다. 로컬 달력 날짜로 3일 이내의 추천만 묻습니다. 별점이나 👍를 고른 가게만 보내며, **안 갔어요**는 기록을 지우고 **✕**는 이번에만 숨깁니다.

## 로컬 실행

`index.html`을 더블클릭하면 브라우저 보안 정책 때문에 동작하지 않아요. 간단한 서버로 띄우세요.

```bash
npx serve .
```

시트 대신 예시 데이터로 보고 싶다면 `PUBLISH_URL`과 `SHEET_ID`를 비우세요.

## GitHub Pages 배포

배포 전에 `npm run bump`를 실행하세요. 로컬 CSS·JavaScript 참조에 같은 시각 버전을 붙여 브라우저 캐시에서 새 파일과 옛 파일이 섞이는 것을 방지합니다. 생성된 `index.html`과 `js/` 변경도 함께 커밋·배포합니다.

저장소 **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 `main` / `(root)`로 지정하면 1~2분 뒤 `https://<계정>.github.io/<저장소>/`에서 열립니다.

## 지역·혼잡도 도입 시 배포 전 작업

1. 구글 폼에 `지역` 질문(단답형, 필수 아님)을 추가합니다. 미리 채워진 링크에서 entry ID를 확인하고 `js/config.js`의 `RATING.entries.region`에 넣습니다.
2. 평점 응답 시트의 `지역` 열에 기존 응답의 지역을 모두 `검암`으로 채웁니다.
3. 가게 탭(점심메뉴·다과(커피)메뉴)에 `지역` 열을 추가해 기존 가게는 모두 `검암`으로 채우고, `혼잡도` 열을 추가합니다(드롭다운 `여유,보통,혼잡` 권장). `사용여부` 열은 삭제합니다. 남아 있어도 앱은 무시합니다.

1·2·3을 마친 뒤 배포하세요. 지역·혼잡도 열 없이도 기존 목록은 동작하지만, region entry가 없으면 평점 기능은 꺼집니다. 지역을 도입하면 기존 평점 행에도 지역을 채워야 이어집니다. 이전 추천 기록은 무효 처리되므로 한 번의 평가 기회를 잃을 수 있습니다.
