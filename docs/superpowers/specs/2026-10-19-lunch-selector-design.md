# 점심 메뉴 추천 사이트 (lunch-selector) 설계

- 작성일: 2026-10-19
- 상태: 사용자 검토 대기 (빌더 체크 반영 완료)

## 1. 의도와 배경

정해진 몇 곳의 음식점 중 오늘 어디로 갈지 매일 점심시간마다 고민하는 것이 일과다. 가게마다 정기 휴무 요일이 달라 "오늘 여는 곳인가"까지 따져야 한다. 이 고민 자체를 없애기 위해, **오늘 영업하는 가게 중에서 1·2·3순위를 무작위로 뽑아주는 사이트**를 만든다.

- 2·3순위가 있는 이유: 1순위가 내키지 않거나, 정기 휴무가 아닌 **임시 휴무**(갑작스러운 휴무, 연휴, 휴가 등)로 닫혀 있을 때 바로 다음 후보로 넘어가기 위함.
- 점심 그룹이 여러 개 있고, 그룹마다 가는 가게가 일부 겹치고 일부 다르다.
- 가게 목록은 **링크에 접근 가능한 누구나** 고칠 수 있어야 한다.
- 혼자 로컬에서 쓰는 것으로 시작했지만, **GitHub Pages로 외부에서도 접속** 가능하게 한다.

## 2. 목표 / 비목표 / 안티목표

**목표**
- 그룹 선택 → (선택) 업종 필터 → 돌리기 → 오늘 영업하는 가게 중 서로 다른 1·2·3순위 표시.
- 정기 휴무 요일인 가게는 자동으로 후보에서 제외.
- 가게 목록은 Google Sheets에서 관리하고, 코드 수정·커밋 없이 시트만 고치면 사이트에 반영.
- 재미있는 뽑기 연출: 감속하며 멈추는 릴 + 폭죽 + 2·3순위 순차 페이드 인.
- 백엔드 없이 정적 파일만으로 동작 (로컬 / GitHub Pages).

**비목표**
- 임시 휴무·연휴·휴가 등 비정형 휴무 처리 (2·3순위로 대응).
- "둘째·넷째 주" 같은 복잡한 휴무 규칙.
- 최근 방문 이력 저장 / 최근 간 곳 덜 나오게 하기 (같은 곳이 연속으로 나와도 괜찮음).
- 사이트 화면에서 가게 목록 편집 (편집은 시트에서).
- 로그인, 사용자 계정, 투표.
- 효과음 (이번 버전 제외).

**안티목표** (동작은 해도 실패로 보는 것)
- 오늘 정기 휴무인 가게가 추천됨.
- 1·2·3순위에 같은 가게가 중복으로 나옴.
- 시트를 고치기 위해 코드나 설정 파일 수정이 필요함 (최초 시트 연결 제외).
- 시트 입력이 조금 어긋났다고(공백, 전각 쉼표 등) 가게가 누락되거나 사이트가 깨짐.

## 3. 제약

- 프론트엔드만 사용 (HTML/CSS/JavaScript). 서버·DB 운영 없음.
- GitHub Pages에 그대로 배포 가능해야 함.
- Google Sheets API 키를 쓰지 않음 → 시트의 공개 CSV 엔드포인트로 읽음.
- 시트 수정 후 사이트 반영까지 구글 캐시로 수 분 지연될 수 있음 (허용).
- 사이트 URL을 아는 사람은 가게 목록을 볼 수 있음 (허용).

## 4. 결정된 사항

### 4.1 데이터: Google Sheets 단일 탭 + 그룹 열 (사용자 결정)

그룹별 탭으로 나누지 않고, **한 탭에 모든 가게를 한 번만** 적고 `그룹` 열로 소속을 표시한다. 겹치는 가게 정보가 한 곳에만 있어 어긋날 일이 없다.

시트 공유 설정: "링크가 있는 모든 사용자 – 편집자" (사용자가 직접 설정). 실수·장난은 구글 시트 버전 기록으로 복구.

**편집 권한 범위 (사용자 결정):** 사이트를 볼 수 있는 사람이면 누구나 시트를 편집할 수 있어도 괜찮다. (gviz 방식은 페이지 소스에 시트 ID가 드러나므로 사실상 그렇게 된다.) 그래서 사이트에 **"가게 목록 편집하기" 링크**를 두어 시트 편집 화면으로 바로 이동하게 한다.

**시트 준비:** 사용자가 직접 만들고 시트 주소를 알려준다. 탭 이름은 `가게목록`. 그 전까지 빌더는 아래 예시 데이터와 같은 내용의 로컬 CSV 파일로 개발하고, 시트 주소를 받으면 실제 시트로 연결을 확인한다.

**시트 배치 규칙:**
- 헤더 첫 셀은 반드시 `A1`. 헤더는 1행에 한 줄로, A열부터 빈칸 없이 이어서.
- 데이터는 2행부터. 중간 빈 행(가게명 빈칸)은 건너뜀.
- 열 순서는 자유, 헤더 이름으로 열을 찾음. 모르는 열은 무시.
- 셀 병합, 2줄 헤더는 사용하지 않음 (README에 안내).

열 구성:

| 열 | 필수 | 형식 | 예 |
|---|---|---|---|
| `가게명` | 필수 | 텍스트. 비어 있으면 그 행은 무시 | 김밥천국 |
| `업종` | 선택 | 쉼표로 여러 개 | `분식,한식` |
| `그룹` | 필수 | 쉼표로 여러 개 | `1팀,2팀` |
| `정기휴무` | 선택 | 요일 한 글자를 쉼표로. 비어 있으면 휴무 없음 | `토,일` |
| `사용여부` | 선택 | 체크박스(TRUE/FALSE). FALSE면 후보 제외. 비어 있으면 사용 | ✅ |
| `메모` | 선택 | 텍스트 | 짬뽕 맛집 |

사용자에게 안내한 예시 데이터 (개발용 CSV도 이 내용으로):

| 가게명 | 업종 | 그룹 | 정기휴무 | 사용여부 | 메모 |
|---|---|---|---|---|---|
| 김밥천국 | 분식,한식 | 1팀,2팀 | 일 | TRUE | |
| 홍콩반점 | 중식 | 1팀 | 토,일 | TRUE | 짬뽕 맛집 |
| 본죽 | 한식 | 2팀 | 일 | TRUE | |
| 진짜맛집 | 중식,한식 | 1팀,2팀 | 월 | TRUE | 점심 특선 있음 |
| 서브웨이 | 양식 | 2팀 | | TRUE | 휴무 없음 예시 |
| 국수나무 | 한식 | 1팀 | 수 | FALSE | 사용 안 함 예시 |

여러 값 칸(`업종`, `그룹`, `정기휴무`) 파싱 규칙: 쉼표(`,`), 전각 쉼표(`，`)로 나누고 각 값의 앞뒤 공백 제거, 빈 값 제거, 중복 제거.

`정기휴무` 요일 값: `월 화 수 목 금 토 일`. `월요일`처럼 써도 첫 글자로 인식. 그 외 알 수 없는 값은 무시하고 콘솔에 경고.

### 4.2 업종 다중 값과 필터 (사용자 결정)

- 필터 버튼은 **현재 선택한 그룹의 가게들**이 가진 업종 값을 개별로 모아 자동 생성 (`중식,한식` → `중식`, `한식` 버튼 각각).
- 버튼 여러 개 선택 시 **OR**: 선택한 업종 중 하나라도 가진 가게가 후보. *(내 결정)*
- 아무 버튼도 선택하지 않으면 전체가 후보. *(내 결정)*
- 업종이 비어 있는 가게는 필터를 하나라도 켜면 제외. *(내 결정)*

### 4.3 추천 로직

후보 = (선택 그룹 소속) ∧ (사용여부 ≠ FALSE) ∧ (오늘 요일 ∉ 정기휴무) ∧ (업종 필터 통과).

- 후보 중에서 균등 무작위로 **서로 다른** 최대 3곳을 뽑아 1·2·3순위로 지정 (Fisher–Yates 셔플 후 앞 3개).
- 가중치·방문 이력 없음.
- 후보가 1~2곳이면 있는 만큼만 표시. 0곳이면 "조건에 맞는 가게가 없어요" 안내. *(내 결정)*
- "오늘 요일"은 브라우저 로컬 시간 기준. *(내 결정 — 사용자가 한국에 있으므로 충분)*

### 4.4 화면 (사용자 결정: 시안 C 룰렛형 + 애니메이션 2번)

위에서 아래로:
1. 제목
2. 그룹 버튼 — `[전체]` + 시트의 `그룹` 열 값들. 한 번에 하나만 선택. `[전체]`는 그룹 구분 없이 모든 가게(그룹이 빈 가게 제외)가 후보 (2026-10-19 사용자 요청으로 드롭다운에서 변경)
3. 업종 필터 버튼 — `[전체]` + 업종들 (토글, 다중 선택). `[전체]`는 아무 업종도 안 켠 상태이며, 누르면 선택이 모두 풀림 (사용자 요청)
4. 릴(가게 이름 한 줄 표시 영역)
5. 돌리기 버튼 (결과 후에는 "다시 돌리기")
6. 2순위·3순위 카드
7. 하단에 작게 "오늘 휴무: ○○, ○○" — 선택 그룹 중 오늘 정기휴무로 빠진 가게 *(내 결정)*
8. 하단에 "가게 목록 편집하기" 링크 — 새 탭으로 시트 편집 화면 열기 (사용자 결정)

**뽑기 연출** (브레인스토밍 시안 2번을 사용자가 "완전 이 형태"라고 확정):
- 돌리기를 누르면 릴의 가게 이름이 빠르게 바뀌다가 **점점 느려지며** 약 2초 뒤 1순위에서 멈춤. 릴에 나오는 이름은 현재 후보에서만 고름.
- 멈추는 순간 1순위 강조(테두리 발광 등) + **폭죽(꽃가루)** 이 터짐.
- 이어서 **2순위 → 3순위가 차례로 아래에서 페이드 인** (약 0.35초 간격).
- 연출 중에는 돌리기 버튼·필터 조작 비활성화.
- 결과 카드에는 가게명 + 업종, `메모`가 있으면 작게 표시. *(내 결정)*
- 참고 시안: `.superpowers/brainstorm/*/content/animation.html` 의 2번 (git 미추적, 로컬에만 있음).

### 4.5 기술 구성

- 순수 HTML/CSS/JavaScript, 빌드 도구 없음. 프레임워크 없음. *(내 결정 — 규모가 작고 GitHub Pages에 그대로 올리기 위함)*
- 시트 연결 정보(스프레드시트 ID, 탭 이름)는 `config.js` 한 곳에 둠. 최초 1회만 설정.
- 데이터 읽기 (사용자 결정: 우선 gviz로 진행): `https://docs.google.com/spreadsheets/d/{ID}/gviz/tq?tqx=out:csv&headers=1&sheet={탭이름}` 를 `fetch`. `headers=1`로 1행을 헤더로 고정 (gviz의 헤더 추측 방지). 시트가 "링크가 있는 모든 사용자" 공유이면 별도 "웹에 게시" 없이 동작하고 CORS 허용됨. *(빌더는 시트 주소를 받는 즉시 실제 시트로 확인할 것)*
- **향후 / 대안: "웹에 게시" CSV.** 사용자가 다음 단계로 이 방식도 해볼 예정이며, gviz가 실제 시트에서 동작하지 않을 때의 대안이기도 함. 주소 형식 `https://docs.google.com/spreadsheets/d/e/2PACX-.../pub?gid=0&single=true&output=csv`. 이를 위해 데이터를 읽는 부분은 "CSV 주소 하나를 받아 가게 목록을 돌려주는" 형태로 분리해, `config.js`에서 gviz 대신 게시 주소를 넣는 것만으로 전환되게 할 것. 이번 범위에서는 게시 방식 전환 자체를 구현·검증할 필요는 없음. (게시 방식은 반영이 최대 5분 정도 지연되고, 편집 링크는 별도로 `config.js`에 둬야 함.)
- CSV 파싱: 따옴표·쉼표·줄바꿈이 들어간 칸을 올바르게 처리해야 함 (직접 구현 또는 PapaParse를 CDN 고정 버전으로).
- 페이지 로드 시 1회 읽음. 로딩 중 표시, 실패 시 "가게 목록을 불러오지 못했어요" + 다시 시도 버튼.
- 마지막 선택 그룹은 `localStorage`에 저장해 다음 방문 시 복원 (읽기·쓰기 실패해도 동작). *(내 결정)*
- 반응형: 휴대폰 폭에서도 사용 가능. *(내 결정)*
- 로컬 실행: `index.html` 더블클릭(file://)에서는 동작을 보장하지 않음. `npx serve` 등 로컬 서버 사용 안내를 README에 적음.
- 예시 시트 구조를 README에 표로 제공.

### 4.6 세부 동작 (내 결정)

- 저장된 그룹이 없거나 저장된 그룹이 시트에서 사라졌으면 그룹 목록의 첫 번째(가나다순)를 선택.
- 그룹이나 업종 필터를 바꾸면 이전 결과는 지우고 초기 상태(릴에 "?")로 돌아감.
- `그룹`이 비어 있는 행은 어떤 그룹에도 나오지 않음 (콘솔 경고).
- `사용여부`는 `FALSE`/`false`/`N`/`아니오`/`0` 일 때만 제외, 그 외 값·빈칸은 사용.
