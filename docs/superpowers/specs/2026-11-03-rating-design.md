# 별점·좋아요 — 설계

- 날짜: 2026-11-03
- 계획: `docs/superpowers/plans/2026-11-03-rating.md`
- 원 설계: `docs/superpowers/specs/2026-10-19-lunch-selector-design.md`

## 왜

다녀온 가게에 대한 동료들의 평가를 결과 카드에서 같이 보고 싶다. 뽑는 순간에는 아직 먹어 보지 않았으니 평가가 의미 없다. **다음에 다시 페이지를 열었을 때** 지난번 추천 가게를 평가하게 한다. 개인 기록은 필요 없고 **가게별 좋아요 총 개수와 평균 별점**만 보이면 된다.

## 원 설계와의 관계

원 설계는 "최근 방문 이력"을 비목표로 뒀다. 이 기능은 익명 평가를 모으는 것이고, 누가 어디에 갔는지 기록하지는 않는다. 다만 "다녀온 곳을 묻는다"는 점에서 그 경계에 닿는다. 사용자 요청으로 이 범위만 연다. 개인 방문 이력, 최근 방문 제외는 여전히 비목표다.

## 전체 구조 (사용자 결정)

```
[돌리기 결과] → localStorage에 "마지막 추천" 저장
[다음 접속]   → 평가 카드 표시 → 구글 폼으로 전송(no-cors POST)
                                   ↓
                        시트의 폼 응답 탭("평점") → 웹에 게시(CSV)
[결과 카드]   ← 앱이 평점 CSV를 읽어 가게별 집계 → 배지 표시
```

- 쓰기 창구는 **구글 폼**이다. Apps Script는 쓰지 않는다. 백엔드 없음 원칙을 유지하고, 몇 분 반영 지연은 감수한다.
- 폼은 기존 시트에 연결한다. 폼이 만든 응답 탭 이름을 "평점"으로 바꾼다.
- 응답 탭은 **숨긴 채로 게시해 읽히는지 먼저 시험**한다. 안 되면 응답을 별도 스프레드시트로 옮긴다. 그래서 앱 설정은 `gid`가 아니라 **평점 CSV 전체 주소**를 받는다. 어느 쪽이든 코드는 같다.
- 익명이다. 로그인, 사용자 식별은 없다.

## 기록 형식

폼 질문 4개. 제목은 정확히 이대로 하고, 모두 단답형, 필수 아님.

| 질문 제목 | 앱이 보내는 값 |
|---|---|
| `모드` | 모드 id (`lunch`, `cafe`) |
| `가게명` | 가게명 그대로 |
| `별점` | `1`~`5`, 고르지 않았으면 빈 값 |
| `좋아요` | 눌렀으면 `1`, 아니면 빈 값 |

- 평가한 가게 하나당 폼 응답 한 건이다.
- 응답 탭 CSV 헤더는 `타임스탬프, 모드, 가게명, 별점, 좋아요`이고, 앱은 **헤더 이름으로** 열을 찾는다.

## 평가 카드 (사용자 결정: 목록형)

> **변경(2026-11-03, 사이클 003):** 표시 방식이 "맨 위 카드"에서 **가운데 모달**로 바뀌고, 버튼에 `다음에`가 추가됐다. 상세는 `docs/superpowers/plans/2026-11-03-rating-modal.md`. 아래 내용 중 표시 위치·닫기 부분은 그 문서가 우선한다.

- 화면 맨 위(모드 버튼 위)에 끼어드는 **카드**다. 화면을 가리는 모달이 아니라서 무시하고 바로 돌려도 된다.
- **가장 최근 돌리기 결과 하나만** 묻는다. 하루에 여러 번 돌렸다면 마지막 결과다.
- 결과가 나온 그 페이지에서는 뜨지 않는다. **다음에 페이지를 열 때(새로고침 포함)** 아래 조건을 본다(사용자 결정).
  - 돌린 시각에서 **30분 이상** 지났으면 띄운다. 아직 30분이 안 됐으면 이번에는 띄우지 않고 지우지도 않는다.
  - **로컬 달력 날짜 기준 3일 이내**(돌린 날 0, 다음 날 1 … 3까지)만 묻는다. 금요일 결과를 월요일에 물을 수 있다. 3일을 넘으면 묻지 않고 지운다.
- 저장 형식(localStorage, 기기 안에만): `{ at: <돌린 시각 epoch ms>, mode: <모드 id>, names: [<1~3순위 가게명>] }`.
- 제목은 `🍽️ 11/3 점심 추천, 다녀온 곳이 있으면 평가해 주세요` 형식이다. 날짜는 저장 시각 기준 `M/D`, 모드 이름은 모드 label에서 이모지를 뺀 것이다.
- 가게(1~3곳)마다 한 줄씩 둔다. 줄에는 가게명, 별 5개(누르면 그 점수, 같은 별을 다시 누르면 해제), 👍 토글이 있다.
- 버튼은 `보내기`, `안 갔어요`, 그리고 카드 오른쪽 위 닫기(`✕`)다.
  - `보내기`: 별점이나 👍 중 하나라도 고른 가게만 전송한다. 하나도 안 골랐으면 버튼은 비활성이다. 전송 중에는 비활성이다.
  - `안 갔어요`: 아무것도 보내지 않고 저장된 결과를 지운다. 다시 묻지 않는다.
  - `✕`: 이번에만 숨긴다. 저장된 결과는 그대로이고, 다음에 페이지를 열 때 다시 묻는다.
- 전송은 가게 하나당 폼 POST 한 번이다. 순서대로 보내고 가게별로 결과를 본다. **보낸 가게는 저장된 결과의 `names`에서 뺀다**(중복 등록 방지). `names`가 비면 저장된 결과를 지운다.
  - 모두 성공(요청이 거절되지 않음): 카드 내용을 `고마워요! 반영까지 몇 분 걸릴 수 있어요`로 바꾸고 잠시 뒤 카드를 숨긴다.
  - 하나라도 실패(네트워크 오류로 거절): `보내지 못했어요. 다음에 다시 물어볼게요`를 띄운다. 실패한 가게만 `names`에 남아 다음에 그 가게만 다시 묻는다. 고르지 않은 가게도 `names`에서 빠진다(보내기를 눌렀다는 것은 평가할 곳을 다 골랐다는 뜻).
  - no-cors라서 폼 쪽 거부(질문 ID 오류 등)는 앱이 알 수 없다. 이건 받아들인다.
- 카드가 떠 있는 동안 새로 돌리면 "마지막 추천"이 새 결과로 바뀐다. 이때 카드는 **자기가 뜰 때 읽은 결과**를 기준으로 동작한다. 카드에서 답해도 더 새로운 결과는 건드리지 않는다(저장된 `at`이 카드의 `at`과 같을 때만 고치거나 지움).
- 저장된 모드가 지금 설정에 없으면 묻지 않고 지운다.

## 결과 카드 배지 (사용자 결정)

- 2·3순위: 카드 오른쪽 위 배지
- 1순위: 릴 박스 오른쪽 위 배지(2·3순위와 같은 위치). 릴이 도는 동안에는 숨기고, 멈춘 뒤 보인다.
- 형식: `★4.2 · 👍12`. 별점이 없으면 `👍12`, 좋아요가 0이면 `★4.2`, 둘 다 없으면 배지를 표시하지 않는다.
- 평균은 소수 첫째 자리까지(반올림)다. 개수(몇 명이 줬는지)는 표시하지 않는다.
- 화면 낭독기용 이름: `평균 별점 4.2점, 좋아요 12개`
- 집계 단위는 **같은 모드 + 같은 가게명**이다(앞뒤 공백 무시). 가게 이름을 바꾸면 이전 평가와 끊긴다. 같은 가게 중복 행을 허용한 결정과 같은 선에서 감수한다.
- 잘못된 값은 집계에서 뺀다. 별점이 1~5 정수가 아니면 별점만 무시하고, 좋아요는 `1`일 때만 센다.
- 상세 시각 디자인(색, 크기, 다크 테마, 긴 가게명과 겹침 처리)은 구현자에게 맡긴다. 기존 칩·강조색 톤을 따른다.

## 평점 읽기

- 앱이 열릴 때 평점 CSV를 한 번 읽는다. 모든 모드가 한 탭에 있다. 가게 목록 로딩을 막지 않는다.
- 실패하거나 시간이 초과되면 조용히 배지 없이 동작한다(콘솔 경고만). 다시 시도 버튼은 없다.
- 제한 시간은 가게 목록과 같은 10초다.
- 방금 보낸 평가는 게시 지연 때문에 바로 보이지 않는다. 앱이 로컬에서 더해 보여주지도 않는다.

## 설정과 꺼짐

`js/config.js`에 평점 설정을 추가한다. 폼 전송 주소(`.../formResponse`), 질문 4개의 `entry.NNN` ID, 평점 CSV 주소다. **하나라도 비어 있으면 평가 기능 전체가 꺼진다.** 카드, 배지, 저장 모두 동작하지 않는다. 카카오 키가 없을 때와 같은 방식이다. 그래서 폼을 만들기 전에도 배포해도 안전하다.

`docs/SETUP.md`에 폼 만들기, 시트 연결, 응답 탭 이름 변경·숨김·게시, `entry` ID 찾는 법 절을 추가한다.

## 비목표

- 개인 평가 기록 보기, 내 평가 수정·취소
- 평가를 뽑기 확률에 반영
- 돌리기 전 목록에서 평가 보기(결과 카드에만 표시)
- 로그인, 강한 조작 방지(같은 사람이 다른 기기·결과로 여러 번 평가하는 것은 막지 않는다)
- 평가 전송 성공 여부의 확실한 확인
- Apps Script, 별도 서버

## PM 판단으로 정한 것

- 일부 전송 실패 시 보낸 가게만 `names`에서 빼고 실패한 가게만 다시 묻는다.
- "3일"은 72시간이 아니라 로컬 달력 날짜 기준이다.
- `✕` 닫기를 추가했다(이번에만 숨김).
- 기록 형식(질문 제목·값), 배지 형식, 평점 읽기 실패 시 조용히 끔, 설정이 비면 기능 전체 꺼짐.
