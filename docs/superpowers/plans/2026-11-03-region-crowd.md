# 지역·혼잡도 Implementation Plan (설계 포함)

> **For agentic workers:** 협업 규약에 따라 코덱스가 구현하고 `docs/agents/handoffs/006-region-crowd.md`의 "구현 보고"를 채운다. **커밋하지 않는다.**

**Goal:** 지역(검암·을지로…)을 그룹 위 단계로 추가해 새 지역을 시트에 적기만 하면 쓸 수 있게 하고, 가게별 혼잡도(경험값)를 결과 카드에 표시한다. 쓰이지 않던 `사용여부` 열을 없애고, 평점이 지역 간에 섞이지 않게 평점 키에 지역을 넣는다.

## 배경 (사용자와 결정, 2026-11-03)

- 지금 그룹은 `3층,4층`. 앞으로 **검암(3층·4층)**, **을지로(9층·10층)**처럼 지역 아래에 그룹을 두고, 그룹이 없는 지역도 생기며, 지역은 계속 늘 수 있다.
- 지역은 서로 가게가 겹치지 않는 별개 묶음이다. 지역을 섞어 뽑을 일은 없다.
- 혼잡도는 "원래 붐비는 곳이라 오늘 자리가 없을 수 있다"를 보고 2순위로 갈지 사람이 판단하는 용도. **표시만** 한다(필터·확률 반영 없음).
- `사용여부`는 실데이터가 전부 TRUE이고, 안 쓰면 행을 지우면 된다 → 삭제.
- 평점은 지금 `모드+가게명` 키라 지역이 다른 같은 이름 가게가 섞인다 → 데이터가 적은 지금 **키에 지역을 넣는다**(사용자 선택: 확실하게).

## 결정

### 1. 시트 형식 (가게 탭: 점심메뉴·다과(커피)메뉴 공통)

| 열 | 필수 | 형식 | 비고 |
|---|---|---|---|
| `지역` | 선택 | 값 하나 (`검암`) | **신규**. 앞뒤 공백 제거 |
| `그룹` | 선택 | 쉼표로 여러 개 | 지역 안에서의 세부 그룹 |
| `혼잡도` | 선택 | `여유` / `보통` / `혼잡` | **신규**. 앞뒤 공백 제거 후 정확히 일치할 때만 인정 |
| `사용여부` | — | — | **삭제**. 열이 남아 있어도 무시 |

나머지 열(가게명·업종·주소·정기휴무·메모)은 그대로.

- `지역` 열이 **없으면** 모든 가게가 이름 없는 하나의 지역(`''`)에 속한다(하위 호환).
- `지역` 열이 있는데 **값이 빈 행**은 어디에도 나오지 않고 `console.warn`(기존 "그룹 빈 행" 경고와 같은 방식). 단, 시트 전체에 지역 값이 하나도 없으면(열만 있고 모두 빈칸) 열이 없는 것과 같이 취급한다.
- 지역 칸에 쉼표가 있으면 첫 값만 쓰고 `console.warn`.
- `혼잡도`에 모르는 값이 있으면 표시하지 않고 `console.warn`. 빈칸은 경고 없이 표시 안 함.

### 2. 후보 규칙

후보 = (선택 지역 소속) ∧ (그룹 조건) ∧ (오늘 요일 ∉ 정기휴무) ∧ (업종 필터 통과)

- 그룹 조건: `[전체]`면 **그 지역의 모든 가게(그룹이 빈 가게 포함)**, 특정 그룹이면 그 그룹을 가진 가게.
  - 기존 규칙 "그룹이 빈 가게는 전체에도 넣지 않는다"는 **폐기**(그룹이 선택 단계가 되었으므로). 그룹 빈 행 경고도 삭제.
- 그룹 칩·업종 칩·오늘 휴무 줄은 **선택한 지역의 가게만**으로 만든다.
- `enabled`(사용여부) 관련 필드·함수·조건 모두 제거.

### 3. 화면

```
① 지역 여러 개 + 선택된 지역 없음 (첫 방문 등)
 [🍱 점심][☕ 카페]                    [테마]
          🍱 오늘 점심 뭐 먹지?
 지역  ( 검암 ) ( 을지로 ) ( 판교 )
        ┌───────────────┐
        │       ?       │
        │ 📍 지역을 먼저 │  ← back-hint 문구 교체
        │  골라 주세요   │
        └───────────────┘
           [ 🎰 돌리기 ]  ← 비활성

② 지역 선택 (그룹 있는 지역)
 지역  [■검암] ( 을지로 ) ( 판교 )
 그룹  [■전체] ( 3층 ) ( 4층 )
 업종  [■전체] (분식) (중식) …

③ 그룹 없는 지역
 지역  ( 검암 ) ( 을지로 ) [■판교]
 업종  [■전체] (한식) …          ← 그룹 줄 숨김
```

- 지역 줄: 기존 그룹 줄과 같은 `filter-label` + `chips` 마크업·스타일. 칩은 가나다순, **`[전체]` 없음**, 하나만 선택(이미 선택된 칩을 다시 눌러도 해제되지 않음).
- 지역 줄 노출: 지역이 **2개 이상**일 때만. 1개(또는 `지역` 열 없음)면 지역 줄을 숨기고 그 지역을 자동 선택 → 지금 화면과 같다.
- 선택된 지역이 없을 때(①): 그룹 줄·업종 줄·오늘 휴무 줄 숨김, 돌리기 비활성, 카드 뒷면 안내 `📍 지역을 먼저 골라 주세요`. 편집 링크는 그대로.
- 지역을 고르면(②③): 그 지역의 그룹 칩(가나다순, 맨 앞 `[전체]`)·업종 칩 표시. 그 지역에 그룹 값이 하나도 없으면 그룹 줄 숨김(③). 결과는 초기화(기존 그룹 변경과 같음), 업종 선택도 초기화.
- 지역이 0개(지역 열은 있는데 모든 행의 지역이 빈 경우는 위 1의 하위 호환 규칙으로 처리되므로, 실제로는 가게가 0개일 때뿐)는 기존 "가게 없음" 처리 그대로.

### 4. 선택 기억 (`localStorage`, 읽기·쓰기 실패해도 동작)

- 지역: 키 `lunch-selector:region`, 값 = 지역 이름. **모드(점심·카페) 공용**.
  - 복원: 저장된 지역이 현재 모드의 지역 목록에 있으면 선택, 없으면 ① 상태(저장값은 지우지 않음 — 다른 모드엔 있을 수 있다). 지역 줄이 숨는 경우(1개)는 자동 선택하되 저장값을 덮어쓰지 않는다.
  - 사용자가 지역 칩을 누를 때만 저장.
- 그룹: 키 `lunch-selector:groups`, 값 = JSON `{ "<지역>": "<그룹>" | "*" }` (`*` = 전체). 지역별로 마지막 그룹을 따로 기억한다.
  - 지역 선택 시 그 지역의 저장 그룹이 현재 그룹 목록에 있으면 그것, 아니면 **`[전체]`**.
  - JSON이 깨졌거나 형식이 다르면 빈 객체로 취급.
  - 이전 키 `lunch-selector:group`(문자열)이 있으면 1회 이전: 처음 복원되는 지역의 그룹 목록에 그 값이 있으면 그 지역 항목으로 옮긴다. 이전 후(성공·실패 무관) 옛 키 삭제.

### 5. 혼잡도 표시

- 1·2·3순위 카드 **모두**에 작은 배지. 1순위(큰 카드)와 2·3순위(작은 카드) 모두.
- 값별 표기: `🟢 여유` / `🟡 보통` / `🔴 혼잡`. 색은 라이트·다크 테마 모두에서 읽히게(텍스트 대비 확보). `aria-label="혼잡도 혼잡"` 형태.
- 위치: 업종·메모 줄(`card-meta`) 근처. 카드 등급 라벨(`card-tier`)·별점 줄(`card-stat`)과 헷갈리지 않게 작게. 상세 시각 디자인은 구현자 재량(기존 톤, 360px 폭, 긴 가게명).
- 값이 없거나 모르는 값이면 배지 없음. 카드 뒷면(돌리기 전)·릴 회전 중에는 표시하지 않음(기존 카드 공개 흐름 그대로).

### 6. 평점 키에 지역

- 키: `ratingKey(mode, region, name)` → `JSON.stringify([mode, region, name])` (모두 trim).
- 집계 `aggregateRatings`: 평점 CSV의 `지역` 열을 읽는다. 열이 없거나 빈 칸이면 지역 `''`.
  - 결과: 가게 시트에 `지역` 열이 없을 때(지역 `''`)는 기존 평점이 그대로 이어진다. `지역` 열을 쓰기 시작하면 **응답 시트의 기존 행 지역을 사용자가 채운다**(아래 7).
- 전송: `RATING.entries.region` 추가 → 폼 본문에 지역을 함께 보낸다.
- `ratingEnabled`: `region` entry도 필수에 포함. 비어 있으면 평점 기능 전체가 꺼진다(지역 없이 보내 데이터가 섞이는 것보다 안전).
- 추천 기록(`last-pick`): `{ at, mode, region, names }`. `parsePick`은 `region`이 문자열(빈 문자열 허용)이 아니면 무효(`null`) → 옛 형식 기록은 버려진다(최대 한 번의 평가 기회 손실, 허용).
- 평가 모달·카드 배지에서 평점을 찾을 때 현재 가게의 지역을 쓴다(모달은 기록의 `region`).

### 7. 사용자 작업 (구현과 별개, 배포 전)

PM이 완료 보고 때 사용자에게 안내한다. 코덱스는 `docs/SETUP.md`에 같은 절차를 적는다.

1. 구글 폼에 질문 `지역`(단답형, 필수 아님) 추가 → 미리 채워진 링크로 `entry.숫자` 확인 → `js/config.js`의 `RATING.entries.region`에 입력.
2. 평점 응답 시트에 생긴 `지역` 열의 기존 행을 모두 `검암`으로 채움.
3. 가게 탭(점심메뉴·다과(커피)메뉴): `지역` 열 추가 후 모두 `검암`, `혼잡도` 열 추가(드롭다운 `여유,보통,혼잡` 권장), `사용여부` 열 삭제.
- 순서: 1·2·3을 마친 뒤 배포하는 것이 안전. 코드는 `지역`·`혼잡도` 열이 없어도 지금처럼 동작한다.

## Global Constraints

- 의존성 추가 금지. 빌드 없음 유지. 동적 문자열은 `textContent`만(`innerHTML` 금지).
- `js/config.js`: `RATING.entries`에 `region: ''` **키 추가만** 허용. 기존 값 변경 금지. (그래서 사용자가 entry ID를 넣기 전까지 평점 기능은 꺼진 상태가 정상이다.)
- 실제 구글 폼 전송 금지. 화면 확인은 저장소 밖 복사본 + 가짜 CSV(지역 2~3개, 그룹 없는 지역 포함, 혼잡도 3종·빈칸·오타 포함).
- 배포 전 버전: 작업 끝에 `npm run bump` 1회(버전 일관성 테스트 통과 상태로).
- 계획과 다르게 해야 할 이유가 생기면 임의로 바꾸지 말고 보고에 질문으로 남기고 멈춘다.
