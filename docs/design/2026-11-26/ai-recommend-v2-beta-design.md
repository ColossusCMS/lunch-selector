## 1. 배경과 목표

v2.4의 `🤖 AI 메뉴 추천`은 실제로는 규칙 기반이다. 날씨에서 성격 태그를 고르는 단계는 규칙이고, AI는 처음 보는 업종의 태그 분류만 한다. 배포 시점의 업종은 모두 시드 태그 표로 덮여 있어 AI가 한 번도 판단에 끼지 않았다. 사용자가 이 점을 지적했다(2026-11-26).

이번 개선의 목표는 세 가지다.
1. **AI가 직접 추천한다.** 서버가 지역별로 날씨 요약과 업종 목록을 AI에 주고, AI가 업종과 안내 문구를 고른다. 결과가 날마다 조금씩 달라지는 것을 의도한다.
2. **베타 안내 팝업을 띄운다.** 팝업 내용은 구글 시트의 `공지` 탭으로 관리한다. 시트가 관리자 화면 역할을 한다.
3. **AI 추천 피드백을 받는다.** 별점과 같은 방식으로, 사이트 안 모달에서 답을 받아 구글 폼으로 보낸다.

### 하지 않는 것
- 서버에 관리자 화면·인증·쓰기 API를 만들지 않는다(공지는 시트로 관리).
- 기기(사용자)마다 AI를 부르지 않는다. 호출은 서버 기준이다.
- 카페 모드는 여전히 추천 대상이 아니다.
- 별점 기능, 추첨 로직, 연출, 지도는 바꾸지 않는다.
- 가게 목록 시트(점심·카페 탭)의 열은 바꾸지 않는다. 시트에는 `공지` 탭 하나만 새로 생긴다.

## 2. 합의된 결정 (2026-11-26)

| 항목 | 결정 |

| 호출 기준 | 서버 기준. 지역마다 **날짜 또는 날씨 분류가 바뀔 때** 다시 부른다. 같은 날·같은 지역이면 모든 사용자가 같은 추천을 본다 |
| 변화 | 날마다 조금씩 달라지는 것을 자연스럽다고 본다. 규칙으로 틀에 맞추지 않는다 |

| 피드백 수집 | 구글 폼(별점과 같은 no-cors POST). 질문 3개 + 숨김 맥락 6개 |
| 버전 | v2.5. 피드백의 앱 버전은 `APP_VERSION`을 자동으로 보낸다 |

## 3. 서버: AI 직접 추천

### 3.1 흐름
```
GET /recommend?region=검암
  ├─ 날씨(30분 캐시) → evaluateWeather → 날씨 분류 key = 날짜(Asia/Seoul) + conditions
  ├─ 시트(10분 캐시) → 그 지역 업종 목록
  ├─ AI 결과 캐시에 (지역, key)가 있으면 → source: "ai" 로 응답
  └─ 없으면 → 규칙 결과로 즉시 응답(source: "rule") + 백그라운드로 AI 추천 작업 시작
```
- `/recommend`는 AI를 기다리지 않는다. 프론트의 3초 제한은 그대로다.
- 서버가 시작하면 설정된 모든 지역에 대해 한 번 AI 추천 작업을 미리 돌린다(첫 사용자도 AI 결과를 보게 하려는 것).
- 날씨 캐시가 새로 갱신돼 분류가 바뀌었으면 그 지역 작업을 다시 시작한다. 분류가 같으면 다시 부르지 않는다.
- 날씨 분류는 `rain`·`hot`·`cold` 조합이고, 아무것도 없으면 `mild`다. 체감온도 수치가 조금 바뀌는 것만으로는 다시 부르지 않는다.

### 3.2 AI 입력 (프롬프트)
- 넘기는 것:
  - 지역 이름, 오늘 날짜와 요일
  - 점심시간 날씨 요약: 분류(비·눈·더움·추움·무난), 체감온도 최저·최고, 강수확률 최대
  - 그 지역 업종 이름 목록(시트 표기 그대로, 20자 초과는 제외, 중복 제거)
- 넘기지 않는 것: 가게 이름, 메모, 주소, 별점, 피드백 내용.
- 요청 내용: "이 목록에서 오늘 점심에 어울리는 업종을 2~6개 고르고, 동료에게 건네는 짧은 한 줄 문구를 써라. JSON `{"categories": [...], "message": "..."}`로만 답하라."
- 문구 톤 예시를 프롬프트에 몇 개 준다(반말, 가벼운 권유, 이모지는 0~1개).
- 실행 방식은 v2.4 분류기와 같다(`--tools ""`, 빈 작업 디렉터리, `--model haiku`, 120초 제한, 표준입력 닫음).

### 3.3 AI 출력 검증
- JSON이 아니거나 `categories`가 배열이 아니면 실패.
- `categories`: 목록에 **정확히 있는 이름**만 남기고 중복을 뺀다. 6개를 넘으면 앞의 6개만 쓴다. 남은 게 1개 미만이면 실패.
- `message`: 문자열이어야 한다. 제어문자와 줄바꿈을 공백으로 바꾸고, 앞뒤 공백을 자르고, 60자를 넘으면 실패로 보고 규칙 문구를 쓴다(업종은 살린다). 비어 있으면 규칙 문구를 쓴다.
- 화면에는 항상 글자(`textContent`)로만 표시한다.

### 3.4 최소 안전장치 (정반대만 막기)
태그 파일을 써서 AI가 고른 업종 중 날씨와 정반대인 것만 뺀다.
- `rain` 또는 `cold`일 때: 태그가 `cold`뿐인 업종(예: 메밀)을 뺀다.
- `hot`일 때: `warm_soup` 태그가 있는 업종을 뺀다.
- `mild`일 때: 빼지 않는다.
- 미분류 업종이나 태그가 `[]`인 업종은 빼지 않는다.
- 안전장치 뒤 남은 업종이 없으면 이 결과는 실패로 보고 규칙 결과를 쓴다.

### 3.5 실패와 재시도
- 실패하면(로그인 만료, 시간 초과, 한도 초과, 검증 실패) 그 (지역, key)는 규칙 결과로 답하고, 30분 뒤 다시 시도한다. 같은 (지역, key)는 하루 최대 3번까지만 시도한다.
- CLI 호출은 서버 전체에서 동시에 하나만 돈다. 업종 분류(v2.4)와 추천 작업은 같은 줄에 선다.
- 결과 캐시는 메모리에만 둔다. 서버를 재시작하면 시작 시 미리 돌리기로 다시 채운다. 날짜가 바뀐 key는 버린다.
- `/health`에 `lastRecommendError`와 지역별 `source`(ai/rule)를 더한다.

### 3.6 규칙 결과 (대체용)
- 비·더움·추움 날은 v2.4와 같다(태그 → 업종).
- 무난한 날의 규칙 결과는 v2.4와 같이 업종 `[]`과 "오늘은 날씨 무난해요. 자유롭게 골라봐"다. AI가 실패한 무난한 날에만 이렇게 보인다.

### 3.7 응답 변경
```json
{
  "ok": true, "region": "검암", "basis": ["weather"],
  "source": "ai",
  "weather": { "conditions": ["rain"], "badge": "☔ 오늘 비", "...": "v2.4와 같음" },
  "message": "비 오는 날엔 뜨끈한 국밥 한 그릇 어때?",
  "categories": ["국밥", "칼국수", "중식"],
  "updatedAt": "..."
}
```
- `source`가 새로 생긴다: `"ai"` 또는 `"rule"`. 빠져 있으면 프론트는 `"rule"`로 본다(v2.4 서버와 호환).
- `categories`는 AI가 고른 순서가 아니라 지금처럼 가나다순으로 정렬한다.
- 배지(`weather.badge`)는 규칙으로 정한다. AI와 상관없다.

## 4. 프론트: 출처 표시

- 안내 문구 아래 작은 글씨를 출처에 따라 바꾼다.
  - `ai`: `🤖 AI 추천 · 검암 점심시간 날씨 기준 · 10:30 갱신`
  - `rule`: `날씨 기준 · 검암 점심시간 날씨 · 10:30 갱신`
- 가이드 카드 첫 줄을 "AI가 오늘 날씨를 보고 어울리는 업종을 골라 켜줘요"로 바꾼다. 나머지는 그대로다.
- 무난한 날에도 업종이 켜질 수 있으므로, 업종 0개 처리(v2.4 남은 사소 항목: "업종 0개를 켰어요" 낭독)를 이번에 함께 고친다. 켤 업종이 없으면 "추천 업종이 지금 화면에 없어요"로 낭독한다.

## 5. 공지 팝업 (구글 시트 `공지` 탭)

### 5.1 시트 양식
가게 목록과 같은 스프레드시트에 공지 탭을 둔다. 사용자가 **`공지관리` 탭(gid `580874591`)**으로 만들었다(2026-11-26). 1행은 아래 열 이름이다. 열 순서는 상관없고 이름으로 찾는다. 영문 열 이름은 대소문자를 가리지 않는다(실제 시트는 `ID`). 체크박스를 미리 깔아둔 빈 행(`사용`=FALSE, 나머지 빈 칸)이 많으므로 빈 행은 조용히 건너뛴다.

| 열 | 필수 | 설명 | 예 |
|---|---|---|---|
| `id` | O | 공지 구별용. 영문·숫자·`-`. 한 번 쓴 id는 다시 쓰지 않는다 | `ai-beta-2026-12` |
| `사용` | O | **체크박스**(삽입 → 체크박스). 체크하면 띄우고, 체크를 풀면 안 띄운다. CSV에는 `TRUE`/`FALSE`로 나온다. 손으로 쓸 때를 대비해 `TRUE`·`O`(영문 대문자 오)·`Y`도 사용으로 인정하고, 그 밖의 값은 미사용이다 | ☑ |
| `시작일` | O | `YYYY-MM-DD`. 그날 0시(한국 시간)부터 | `2026-12-01` |
| `종료일` |  | `YYYY-MM-DD`. 그날 끝까지 포함. 비우면 계속 | `2026-12-31` |
| `제목` | O | 한 줄 | `🤖 AI 메뉴 추천 베타 오픈` |
| `내용` | O | 여러 줄 가능(셀 안 줄바꿈 그대로 표시) | |
| `버튼` |  | 추가 버튼 문구. `링크`와 함께 쓴다 | `자세히 보기` |
| `링크` |  | `https://`로 시작하는 주소만 인정. 새 창으로 연다 | |

- 띄우기·내리기는 `사용` 체크박스로, 기간은 시작일·종료일로 한다.
- 시트를 고친 뒤 사이트에 반영되기까지 몇 분 걸린다(웹에 게시 갱신 주기).
- 게시된 내용은 누구나 볼 수 있다. 비밀 내용을 쓰지 않는다.

### 5.2 표시 규칙
- 페이지를 열 때 `공지` 탭 CSV를 읽는다. 가게 목록 읽기와 따로 돌고, 실패하면 아무것도 띄우지 않는다(조용히 무시).
- 조건(`사용` 체크, 오늘이 기간 안, 필수 칸이 있음, 사용자가 숨기지 않음)을 만족하는 공지를 **차례로 띄운다**(9절 1번). 순서는 시작일이 늦은 것부터, 같으면 시트에서 아래쪽 행부터다. 한 번 접속에 **최대 3개**까지만 띄운다.
- 하나를 닫으면(어떤 버튼이든) 다음 공지를 이어서 띄운다. 공지가 2개 이상이면 제목 옆에 `1/3`처럼 순서를 보인다. 숨김 버튼은 지금 보고 있는 공지에만 적용된다.
- 같은 `ID`가 여러 행에 있으면 아래쪽 행 하나만 쓴다.
- 내용은 모두 글자로만 표시한다(HTML 해석 안 함). 시트 편집 권한이 있는 사람이 사이트에 스크립트를 넣을 수 없게 하려는 것이다.
- 버튼
  - **오늘 하루 안 보기**: 그 공지 id를 오늘 날짜와 함께 저장한다. 다음 날 다시 뜬다.
  - **다시 띄우지 않기**: 그 공지 id를 영구로 저장한다.
  - **닫기(✕, Esc)**: 이번에만 닫는다. 다음 접속 때 다시 뜬다.
  - `버튼`+`링크`가 있으면 링크 버튼을 하나 더 둔다. 눌러도 공지는 닫히지 않는다.
- 저장 키: `lunch-selector:notice-hidden` (`{ "<id>": "forever" | "YYYY-MM-DD" }`). 기존 `storage` 헬퍼를 쓴다. 지난 날짜 값은 읽을 때 정리한다.
- `<dialog>`로 만든다. 별점 카드·제외 확인·공개 연출 dialog가 열려 있으면 띄우지 않는다.
- **별점 카드와 겹칠 때**: 공지를 먼저 띄우고, 마지막 공지를 닫은 뒤 별점 카드 조건을 다시 확인해서 띄운다.

### 5.3 설정
- `js/config.js`에 `NOTICE = { gid: '580874591' }`를 둔다. gid가 비면 공지 기능이 꺼진다. 주소는 `PUBLISH_URL` + gid로 만든다(가게 목록과 같은 방식).

### 5.4 첫 공지 (사용자가 시트에 입력)
문구는 사용자가 다듬는다. 초안:
- 제목: `🤖 AI 메뉴 추천 베타를 시작했어요`
- 내용:
  ```
  오늘 날씨를 보고 AI가 어울리는 업종을 골라줘요.
  제목 아래 [🤖 AI 메뉴 추천]을 켜면 바로 써볼 수 있어요.
  써보고 느낀 점은 화면 아래 [🤖 AI 추천 피드백]으로 알려주세요.
  ```

| `weather` | 날씨 | `entry.129957015` | `비 · 체감 3~6℃ · 강수 80%` 형식 |
| `categories` | 추천 업종 | `entry.1251237933` | `국밥, 칼국수, 중식` (없으면 빈 값) |
| `source` | 추천 출처 | `entry.341670665` | `ai` / `rule` / `off`(추천을 끈 채 연 경우) |
| `store` | 뽑힌 가게 | `entry.577077389` | 마지막 결과의 1순위 가게 이름(없으면 빈 값) |
| `version` | 앱 버전 | `entry.512805220` | `APP_VERSION` |

- `js/config.js`에 `FEEDBACK = { formUrl, entries: {...} }`를 둔다. 하나라도 비면 피드백 기능(자동 표시와 하단 버튼)이 꺼진다. `ratingEnabled`와 같은 모양의 `feedbackEnabled`를 둔다.

### 6.2 모달 구성 (별점 카드와 같은 스타일)
- 제목: `🤖 AI 추천 어땠어요?` 와 작은 글씨 `베타 기능이라 의견이 큰 도움이 돼요`
- 질문 1·2: 별 5개 버튼(별점 카드의 별 버튼 재사용). 둘 다 골라야 [보내기]가 켜진다.
- 질문 3: 여러 줄 입력칸, 선택, 500자 제한.
- 버튼: [나중에] / [보내기]. 보내는 동안 [보내기]를 막는다. 보낸 뒤 "고마워요! 의견 잘 받았어요"를 잠깐 보이고 닫는다.
- 숨김 맥락은 화면에 보이지 않는다.

### 6.3 언제 띄우나
- **자동 표시(한 번)**: 점심 모드에서 AI 추천이 켜진 상태로 룰렛 결과가 나오고(공개 연출이 끝나 결과 카드가 보인 뒤), 아직 자동 표시를 한 적이 없으면 띄운다. 띄우는 순간 "자동 표시함"을 저장한다. 보내든 [나중에]로 닫든 다시 자동으로 뜨지 않는다.
- **하단 버튼**: `footer`에 `🤖 AI 추천 피드백` 버튼을 둔다. 피드백 설정이 있고 `RECOMMEND_URL`이 있으면 모드와 상관없이 보인다. 언제든 연다.
- 다른 dialog가 열려 있으면 자동 표시는 그 dialog가 닫힐 때까지 미룬다.
- 저장 키: `lunch-selector:feedback-prompted` (`1`).

## 7. 테스트 (Node `node:test`, 외부 네트워크 없이)
- 서버
  - AI 추천 출력 검증: JSON 아님, 목록에 없는 업종, 중복, 7개 이상, 0개, 문구 길이·제어문자·빈 값
  - 안전장치: rain/cold에서 cold 전용 업종 제외, hot에서 warm_soup 제외, mild는 그대로, 전부 빠지면 규칙 대체
  - 캐시 key: 같은 날 같은 분류면 재호출 안 함, 분류가 바뀌면 재호출, 날짜가 바뀌면 재호출
  - 실패 재시도 간격(30분)과 하루 3회 상한, CLI 동시 실행 1개
  - 응답의 `source`, AI 결과가 없을 때 규칙 응답 즉시 반환
- 프론트
  - `parseRecommendation`: `source` 없음 → `rule`
  - 공지: CSV 파싱(열 이름으로 찾기, 셀 안 줄바꿈), 기간 판정(한국 날짜, 종료일 포함), `사용` 값, 필수 칸 누락, 숨김 저장 해석과 정리, 여러 개 중 고르기, `https://` 아닌 링크 무시
  - 피드백: `feedbackEnabled`, 전송 본문 조립(entry 매핑, 날씨 문자열, 500자 자르기), 자동 표시 판정
- 기존 144개 테스트는 그대로 통과해야 한다.
- 실제 구글 폼 전송은 하지 않는다. 화면 확인 때도 `fetch`를 가로채서 확인한다.
