- 작성: lunch-selector PM(클로드), 2026-11-25

## 1. 목표

점심 모드에서 사용자가 **`🤖 AI 메뉴 추천`** 을 켜면, 오늘 그 지역의 점심시간 날씨에 어울리는 업종 버튼이 자동으로 켜진다. 사용자는 켜진 버튼을 언제든 직접 바꿀 수 있다. 추천 근거는 지금은 날씨 하나이고, 나중에 다른 근거를 더할 수 있게 구조를 잡는다.

### 하지 않는 것
- 카페 모드는 대상이 아니다. 카페 탭의 업종은 모두 `카페`다.
- 추첨 로직, 정기휴무 거르기, 별점과 카드 등급, 제외 기능, 연출, 지도는 바꾸지 않는다.
- 가게 목록 읽기는 지금처럼 프론트가 시트 CSV를 직접 읽는다. 백엔드를 거치지 않는다.
- 시트 양식은 바꾸지 않는다. 열을 추가하지 않는다.
- 날씨 외의 추천 근거(요일, 별점 등)는 이번 범위가 아니다.
- 추천 문구는 사용자가 나중에 다듬는다. 이번에는 아래 초안 문구를 쓴다.

## 3. 전체 구조

```
[브라우저: GitHub Pages]
  ├─ 시트 CSV 직접 읽기 (지금과 같음)
  └─ GET {RECOMMEND_URL}/recommend?region=검암   ← 새로 추가, 실패하면 무시
           │
[사용자 리눅스 서버: Docker 컨테이너 lunch-recommend]
  ├─ Open-Meteo 날씨 조회 (지역 좌표, 30분 캐시)
  ├─ 시트 점심 탭 CSV 읽기 (업종 목록, 10분 캐시)
  ├─ data/category-tags.json  (업종 → 태그, 사람이 고칠 수 있음)
  └─ 미분류 업종이 있으면 백그라운드로 `claude -p` 한 번 호출 → 태그 파일에 추가
```

`/recommend` 응답은 AI 호출을 기다리지 않는다. 그 시점에 태그 파일에 있는 정보만으로 답하고, 분류는 뒤에서 따로 돈다.

## 4. 백엔드

### 4.1 위치와 실행
- 코드 위치: 같은 저장소의 `server/` 폴더 (8절 1번 확정).
- Node.js 22 이상, **외부 패키지 없음**. `node:http`와 내장 `fetch`만 쓴다. 테스트는 기존과 같은 `node:test`를 쓴다.
- 시트 CSV 파싱은 프론트의 `js/csv.js`, `js/stores.js`, `js/data.js`(`loadStores`)를 그대로 import 한다. 기존 테스트도 Node에서 이 모듈들을 import 하고 있다.
- 배포: `server/Dockerfile`과 `server/compose.example.yml`을 둔다.
  - 이미지에 Claude Code CLI를 설치한다. 설치 명령은 구현 시점의 공식 안내를 따른다.
  - CLI 로그인 정보가 컨테이너 재시작 뒤에도 남도록 홈 디렉터리의 Claude 설정 경로를 볼륨으로 둔다. 정확한 경로는 구현 시 확인한다.
  - 첫 로그인은 사용자가 `docker exec -it lunch-recommend claude`로 들어가서 한다.
  - `data/` 폴더(태그 파일)도 볼륨으로 둔다.

### 4.2 설정 파일 `server/config.json`
```json
{
  "port": 8787,
  "allowedOrigins": ["https://colossuscms.github.io", "http://localhost:5173"],
  "sheetCsvUrl": "<점심 탭 게시 CSV 주소, js/config.js의 PUBLISH_URL + gid 0>",
  "regions": {
    "검암":   { "lat": 37.569, "lon": 126.674 },
    "을지로": { "lat": 37.566, "lon": 126.992 }
  },
  "lunchHours": [11, 12, 13],
  "classifier": "claude"
}
```
- 지역 키는 시트의 `지역` 값과 정확히 같아야 한다.
- `classifier`: `"claude"`면 미분류 업종을 CLI로 분류하고, `"off"`면 분류하지 않는다(미분류는 추천에서 빠진다). 로그인 전이나 점검할 때 쓴다.
- 설정은 서버를 시작할 때 한 번 읽는다. 지역을 추가하면 컨테이너를 재시작한다.
- 설정에 없는 지역으로 요청이 오면 `404`와 `{ "ok": false, "reason": "unknown-region" }`을 돌려주고, 서버 로그에 "좌표 없음: <지역>"을 남긴다.

### 4.3 API

`GET /recommend?region=<지역>`

```json
{
  "ok": true,
  "region": "검암",
  "basis": ["weather"],
  "weather": {
    "conditions": ["rain", "cold"],
    "badge": "☔ 오늘 비",
    "apparentMin": 3.1,
    "apparentMax": 6.0,
    "precipitationProbabilityMax": 80
  },
  "message": "비 오는 날엔 국물이나 튀김 어때?",
  "categories": ["감자탕", "국밥", "돈까스", "중식", "찌개"],
  "updatedAt": "2026-11-25T10:30:00+09:00"
}
```
- `conditions`가 비어 있으면(무난한 날) `categories`는 `[]`, `badge`는 `""`이고, `message`는 "오늘은 날씨 무난해요. 자유롭게 골라봐"다.
- `categories`는 **그 지역 가게에 실제로 있는 업종 이름**만, 시트에 적힌 표기 그대로 담는다.
- `updatedAt`은 응답 시각이 아니라 **날씨 데이터를 받아온 시각**이다(brain `stale-display-needs-freshness-indicator`).
- 날씨 조회에 실패했는데 캐시도 없으면 `503`과 `{ "ok": false, "reason": "weather-unavailable" }`을 돌려준다.
- CORS: `allowedOrigins`에 있는 출처에만 `Access-Control-Allow-Origin`을 붙인다. `GET`만 허용한다.

`GET /health` → `{ "ok": true, "untagged": <미분류 업종 수>, "lastClassifyError": <문자열 또는 null> }`. 사용자가 서버 상태를 볼 때 쓴다.

### 4.4 날씨 판정
- Open-Meteo forecast API를 부른다. 파라미터: `hourly=apparent_temperature,precipitation_probability,precipitation,weather_code`, `timezone=Asia/Seoul`, `forecast_days=1`.
- 오늘의 `lunchHours`(11·12·13시) 값만 본다.

| 조건 | 판정 기준 (점심 시간대) | 켜는 태그 | 배지 |
|---|---|---|---|
| `rain` | 강수확률 최댓값 ≥ 60, 또는 강수량 > 0, 또는 비·눈 계열 날씨 코드(51–67, 71–77, 80–86, 95–99) | `warm_soup`, `greasy` | ☔ 오늘 비 (눈 코드면 ❄️ 오늘 눈) |
| `cold` | 체감온도 최솟값 ≤ 5℃ | `warm_soup` | 🥶 오늘 쌀쌀 |
| `hot` | 체감온도 최댓값 ≥ 28℃ | `cold`, `light` | 🥵 오늘 더움 |

- 여러 조건이 겹치면 태그는 합친다. 배지와 문구는 `rain` → `hot` → `cold` 순서로 앞의 것 하나를 쓴다.
- 문구 초안:
  - rain: "비 오는 날엔 국물이나 튀김 어때?"
  - cold: "쌀쌀하니까 뜨끈한 국물로"
  - hot: "더우니까 시원하고 가볍게 가자"
- 기준값(60%, 5℃, 28℃)과 문구는 `server/rules.js` 한곳에 상수로 둔다.

### 4.5 업종 태그
- 태그는 4종이다.

| id | 표시명 | 예 |
|---|---|---|
| `warm_soup` | 따뜻한 국물 | 국밥, 순댓국, 감자탕, 찌개, 전골, 해장, 칼국수, 우동, 쌀국수 |
| `cold` | 시원함 | 메밀, 냉모밀 |
| `greasy` | 기름짐·튀김 | 돈까스, 치킨, 중식, 고기, 곱창 |
| `light` | 가벼움 | 샐러드, 포케, 샌드위치, 베이글, 김밥 |

- `한식`, `일식`, `양식`처럼 범위가 넓은 업종은 `[]`(태그 없음)이 정상이다.
- 저장 형식 `data/category-tags.json`:
  ```json
  { "version": 1, "tags": { "국밥": ["warm_soup"], "한식": [], "돈까스": ["greasy"] } }
  ```
  - 키가 **없으면** 미분류다. `[]`이면 "분류했고 해당 태그 없음"이다. 두 경우를 구분한다.
  - AI는 **없는 키만 추가**하고, 있는 키는 절대 덮어쓰지 않는다. 그래서 사람이 고친 줄은 그대로 남는다.
  - 파일은 임시 파일에 쓴 뒤 이름을 바꾸는 방식으로 저장한다. 쓰다가 죽어도 파일이 깨지지 않게 하려는 것이다.
- 초기 파일: 구현 단계에서 2026-11-25 시점의 업종 약 50종을 위 기준으로 미리 채워서 넣는다. PM이 리뷰한다.

### 4.6 AI 분류 (`claude -p`)
- 시트를 새로 읽었는데 미분류 업종이 있으면, **한 번에 묶어서** CLI를 한 번 호출한다. 동시에 하나만 돈다.
- 프롬프트에는 **업종 이름만** 넣는다. 가게명, 메모, 주소, 별점은 넣지 않는다. 업종 이름은 앞뒤 공백을 자르고 20자를 넘으면 뺀다.
- 기대하는 출력은 `{"<업종>": ["warm_soup", ...], ...}` 형태의 JSON이다.
- 응답 검증:
  - JSON이 아니면 전체를 실패로 처리한다.
  - 요청하지 않은 업종 키는 버린다.
  - 허용되지 않은 태그 값은 버린다.
  - 값이 배열이 아니면 그 업종만 미분류로 남긴다.
- **프롬프트 주입 대비**: 업종 값은 시트 편집자가 자유롭게 쓰는 문자열이다. 그래서 CLI는 도구 사용을 끈 상태로, 빈 작업 디렉터리에서 실행한다. 출력은 위 검증을 통과한 태그로만 반영하므로, 최악의 경우에도 태그가 잘못 붙는 데서 끝난다. 정확한 플래그(도구 비활성화, 모델 지정, 출력 형식)는 구현 시 `claude --help`로 확인한다.
- 시간 제한은 120초다. 실패하면(로그인 만료, 시간 초과, 한도 초과, 검증 실패) 그 업종들은 미분류로 남는다. `lastClassifyError`에 사유를 남기고 **1시간 뒤에 다시 시도**한다. 미분류 업종은 추천에서만 빠지고, 룰렛에는 그대로 나온다.

## 5. 프론트엔드

### 5.1 설정
- `js/config.js`에 `export const RECOMMEND_URL = '';`를 추가한다. 비어 있으면 기능 전체가 꺼지고 `추천` 줄이 숨겨진다. 카카오 키를 비우면 지도가 꺼지는 것과 같은 방식이다.

### 5.2 새 모듈 `js/recommend.js` (DOM 없는 순수 함수 중심)
- `buildRecommendUrl(base, region)`
- `parseRecommendation(json)`: 필수 필드를 검사하고 결측이면 기본값을 넣는다. 형식이 틀리면 `null`을 돌려준다(brain `db-column-as-api-contract`).
- `fetchRecommendation(url, fetchFn, { timeout = 3000 })`: `AbortController`로 3초 제한을 건다. 실패하면 `null`을 돌려준다.
- `pickVisibleCategories(recommended, visibleCategories)`: 지금 화면에 보이는 업종 버튼과의 교집합이다. 그룹을 고르면 보이는 업종이 줄어들기 때문에 필요하다.

### 5.3 화면 (샘플과 같음)
- 제목(`h1`)과 지역 줄 사이에 `filter-row`를 하나 추가한다. 라벨은 `추천`이다.
  - 켜기·끄기 버튼 `🤖 AI 메뉴 추천` (`aria-pressed`)
  - 날씨 배지 (꺼져 있을 때만, `badge`가 있을 때만)
- 추천 줄 아래 안내 문구 (켜져 있을 때만): `message` + 작은 글씨 "🤖 AI 추천 · <지역> 점심시간 날씨 기준 · <updatedAt의 HH:mm> 갱신"
- 가이드 카드: 처음 켤 때 한 번 화면 오른쪽 아래에 띄운다. [확인]으로 닫는다. 내용은 샘플의 세 줄이다.

### 5.4 동작
- **추천 줄을 숨기는 경우**: `RECOMMEND_URL`이 비어 있음, 카페 모드, 지역이 아직 정해지지 않음, 요청 실패, `ok: false`.
- **요청 시점**: 점심 모드에서 지역이 정해질 때(첫 로딩, 지역 변경). 켜짐·꺼짐과 상관없이 요청한다(배지에 필요). 지역별 응답은 페이지에 있는 동안 메모리에 캐시한다.
- 늦게 온 옛 응답은 버린다. 기존 `createRequestCounter` 패턴을 그대로 쓴다.
- **켜짐**:
  - 켜는 순간, 그리고 지역·그룹이 바뀌어 업종 선택이 초기화될 때마다 `pickVisibleCategories` 결과로 `state.categories`를 채운다.
  - 결과가 비면 업종은 [전체] 상태로 둔다.
  - 그 뒤 사용자가 업종 버튼을 직접 누르는 건 지금과 똑같이 동작한다.
- **끄는 순간**: 업종 선택을 [전체]로 되돌린다(8절 3번).
- **저장 키**(기존 `lunch-selector:` 접두어를 따름): `lunch-selector:recommend` (`on`/`off`), `lunch-selector:recommend-guide-seen`. 읽고 쓰는 것은 모두 기존 `storage` 헬퍼(try/catch)를 거친다.
- 추천 응답이 늦게 와도 룰렛 버튼과 로딩을 막지 않는다.

## 8. 결정 (2026-11-26 사용자 확정)
1. 서버 코드는 **같은 저장소의 `server/`** 에 둔다. GitHub Pages로 코드가 보여도 비밀값이 없어서 문제없다.
