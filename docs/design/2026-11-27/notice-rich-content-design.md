- 작성: PM(클로드), 2026-11-27
- 상태: 합의 완료(2026-11-27), v2.6
- 기준: v2.5(`f7f2036`). 관련 인계 `docs/agents/handoffs/030-notice-feedback.md`, 운영 문서 `docs/SETUP.md` "공지 팝업"

## 1. 배경

지금 공지 내용은 `textContent`와 `white-space: pre-line`으로 글자만 보여준다(`js/dialogs.js` `showNotice`). 시트 셀에서 굵게나 색을 바꿔도 웹 게시 CSV에는 서식이 담기지 않으므로 사이트에 넘어오지 않는다. 사용자는 이 점이 제한적이라고 보고 다음 세 가지를 원했다.

- 이미지를 넣을 수 있어야 한다.
- 굵게, 색 같은 간단한 스타일을 쓸 수 있어야 한다.
- 링크를 여러 개 넣을 수 있어야 한다.

## 3. 문법 명세

문법은 `내용` 칸에만 적용한다. `제목`과 `버튼`은 지금처럼 글자 그대로 보여준다.

### 3.1 블록 (줄 단위)
- 셀 안의 줄바꿈(`\n`, CSV의 `\r\n` 포함)으로 줄을 나눈다.
- `- `(하이픈 + 공백)으로 시작하는 줄은 목록 항목이다. 이어진 항목들은 하나의 점 목록으로 묶는다. 하이픈 앞의 공백은 허용한다. 들여쓰기 중첩 목록은 지원하지 않는다.
- 앞뒤 공백을 뺀 줄 전체가 `{이미지:…}` 하나이면 이미지 줄이다. 규칙은 4절에 있다. 글 중간에 섞인 `{이미지:…}`는 해석하지 않고 글자로 둔다.
- 그 밖의 줄은 글 줄이다. 연속된 글 줄은 하나의 문단으로 묶고 줄바꿈을 유지한다. 빈 줄은 문단을 나눈다.

### 3.2 인라인 — `{종류:내용}`
| 종류 | 형식 | 결과 |
|---|---|---|
| 굵게 | `{굵게:중요}` | 굵은 글씨 |
| 색 글자 | `{빨강:마감 임박}` | 색 글자. 종류 이름은 `빨강`·`파랑`·`초록`·`주황` |
| 링크 | `{링크:신청하기\|https://...}` | 새 탭(`target="_blank"`, `rel="noopener"`)으로 여는 링크 |

예시(사용자 확인본):
```
{이미지:beta-poster.png|베타 안내}
이번 주 {굵게:AI 추천 베타}를 시작해요.
{빨강:12/5까지} 의견을 남겨 주세요.
- 비 오는 날엔 국물 위주로 추천해요
자세한 내용은 {링크:안내 문서|https://...}에서 확인해 주세요.
```

해석 규칙:
- 여는 `{`는 바로 뒤에 아는 종류 이름과 `:`가 올 때만 문법으로 본다. 종류 이름은 `굵게`·`빨강`·`파랑`·`초록`·`주황`·`링크`·`이미지`로 고정한다. 그 밖의 `{`는 글자다.
- 닫는 `}`는 중괄호 깊이를 세어 짝을 찾는다. 같은 줄 안에 짝이 없으면 여는 부분(`{굵게:`)을 글자로 두고 나머지를 계속 해석한다.
- 굵게와 색 글자의 내용은 다시 해석하므로 서로 감쌀 수 있다. 예: `{굵게:{빨강:오늘 마감}}`, `{파랑:{굵게:오늘}만 할인}`. 중첩 깊이는 4단계까지만 해석하고, 그보다 깊으면 글자로 둔다.
- 링크는 내용을 첫 `|`에서 나눠 앞은 글씨, 뒤는 주소로 본다. 그래서 링크 글씨에는 `|`를 쓸 수 없다. 주소는 앞뒤 공백을 빼고 기존 `httpsLink` 검사(`https://`로 시작하고 `URL` 파싱이 되는 경우)를 통과해야 한다. `|`가 없거나, 글씨가 비었거나, 주소가 통과하지 못하면 그 문법 전체를 글자로 둔다. 링크 글씨는 해석하지 않는다.
- 내용이 빈 문법(`{굵게:}`)은 전체를 글자로 둔다.
- 기호를 글자로 쓰는 탈출 문법은 두지 않는다. 아는 종류 이름 뒤에 `:`가 붙은 경우만 문법이므로, 일반 중괄호는 그대로 글자로 나온다. 필요해지면 후속으로 다룬다.
- 한 줄을 넘어가는 인라인 문법은 없다.

### 3.3 안전 원칙
- 파서는 DOM과 무관한 순수 함수(`js/notice-markup.js`)로 만들고, 결과는 노드 배열(예: `{type:'bold', children:[…]}`, `{type:'text', value}`)이다. Node 테스트로 검사한다.
- 화면 쪽은 노드 배열을 `createElement`와 `textContent`로만 그린다. `innerHTML`, `insertAdjacentHTML`, 사용자 값을 넣은 `style` 속성은 쓰지 않는다.
- 색은 CSS 클래스(`notice-color-red` 등)로만 적용한다. 시트 값이 클래스 이름으로 그대로 들어가지 않게 색 이름 → 클래스 대응표를 코드에 고정한다.
- 링크 주소는 `httpsLink`를 통과한 값만 `href`에 넣는다.

### 3.4 색 토큰
- `:root`에 `--notice-red`, `--notice-blue`, `--notice-green`, `--notice-orange`를 두고, 기존 테마 방식(`prefers-color-scheme` + `:root:not([data-theme='light'])`, `:root[data-theme='dark']`)으로 다크 값을 따로 정한다.
- 라이트·다크 각각 팝업 배경 대비 4.5:1 이상을 목표로 한다. 구현 시 실제 값과 대비를 계산해 보고한다.

## 4. 이미지

### 4.1 문법과 파일
- 형식: 한 줄 전체가 `{이미지:파일 이름|설명}` 또는 `{이미지:파일 이름}`. 예: `{이미지:beta-poster.png|베타 안내 포스터}`. 첫 `|`에서 나누고, 파일 이름은 앞뒤 공백을 뺀다.
- 파일 이름은 정규식 `^[A-Za-z0-9_-]{1,60}\.(png|jpe?g|webp|gif)$`(대소문자 무시)만 받는다. 경로 구분자, `..`, 주소(`https://` 포함), 공백은 모두 이 검사에서 걸러진다. 통과하지 못한 줄은 글 줄로 보고 글자 그대로 보여준다.
- 사이트는 `images/notice/<파일 이름>`(페이지 기준 상대 경로)으로 불러온다.
- `설명`은 `alt`가 된다. 없거나 비어 있으면(`{이미지:a.png}`) 공지 제목을 `alt`로 쓴다. 설명 안의 문법은 해석하지 않는다.
- 한 공지에 이미지는 최대 3장이다. 넷째 이미지 줄부터는 글 줄로 본다.
- 저장소에 `images/notice/` 폴더를 만들고 `.gitkeep` 등으로 유지한다.

### 4.2 공지 유효성
- 바뀌지 않는다. `내용`은 계속 필수이고, 이미지 줄 하나만 있어도 내용이 있는 것으로 본다. 시트 칸도 늘지 않는다.

### 4.3 화면
- 순서: 닫기 → 제목(+ `1/3`) → 내용(글·목록·이미지가 적힌 순서대로) → 하단 버튼 → `오늘 하루 안 보기`·`다시 띄우지 않기`.
- 이미지는 팝업 폭에 맞추고(`width: 100%`, `height: auto`), 세로는 `max-height: 50vh`로 제한하며 `object-fit: contain`으로 잘리지 않게 줄인다. 모서리는 기존 팝업 톤에 맞춰 둥글게 한다.
- 불러오기에 실패하면(`error` 이벤트) 그 이미지 요소만 지운다. 이미지만 있던 공지라면 제목과 버튼만 남는다.
- 이미지 때문에 팝업이 화면보다 길어지면 팝업 안에서 스크롤된다(기존 모달 스크롤 동작 확인 필요).
- 이미지에는 크기 속성이 없으므로 불러오는 동안 팝업 높이가 바뀔 수 있다. 첫 포커스 이동 뒤 레이아웃이 밀리는 정도는 허용한다.

### 4.4 캐시 주의 (운영)
- `npm run bump`는 CSS·JS에만 버전을 붙인다. 이미지는 브라우저와 GitHub Pages가 캐시할 수 있으므로, **이미지를 바꿀 때는 같은 이름으로 덮어쓰지 말고 새 파일 이름을 쓴다.** SETUP에 적는다.
- 순서: 이미지 파일을 커밋·푸시해 Pages에 반영된 것을 확인한 뒤, 시트 `내용`에 이미지 줄을 적는다.

## 5. 하단 버튼

- 시트 규칙은 그대로다(`링크`가 유효한 https일 때만 표시, `버튼`이 비면 `자세히 보기`).
- 모양만 바꾼다. 지금의 강조색 굵은 글씨 링크(`.notice-link`)를 강조색 배경의 버튼 모양 링크로 바꾼다. 요소는 계속 `<a>`이고, 폭은 팝업 폭에 맞춘다. 기존 `.recommend-guide button`, `.rating-send`의 모양을 참고해 통일감을 맞춘다.
- 첫 포커스는 지금처럼 하단 버튼(없으면 `오늘 하루 안 보기`)이다.

## 7. 테스트 기준 (요지)

- 문법: 굵게·색·링크 각각, 굵게·색 중첩, 4단계 초과 중첩, 닫는 `}` 없음, 모르는 종류 이름(`{보라:…}`)과 일반 중괄호가 글자로 남는지, 빈 내용, 링크의 `|` 없음·빈 글씨·http·`javascript:` 거부, 링크 글씨 안 문법 미해석, 목록 묶기와 목록·문단 전환, `\r\n`, 빈 줄로 문단 나누기, HTML처럼 보이는 글자(`<b>`, `<img onerror>`)가 글자 노드로 남는지.
- 이미지 줄: 정상 파일 이름, 확장자 대소문자, 경로·`..`·주소·공백·61자 거부(글 줄로 남는지), 글 중간 `{이미지:…}` 미해석, 설명 없음·빈 설명 → 제목 alt, 넷째 이미지부터 글 줄, 목록 사이에 낀 이미지 줄의 목록 끊김, 이미지 줄만 있는 공지가 `parseNotices`를 통과하는지.
- 기존 공지 테스트는 모두 그대로 통과해야 한다.

## 8. 하지 않는 것

- 시트 HTML 허용, 외부 이미지 주소, 글자 크기·밑줄·제목 문법, 중첩 목록, 탈출 문법.
- 하단 버튼 두 개 이상.
- 별점 카드·피드백 모달 변경.

## 9. 확장성

- 문법 해석은 서버가 아니라 사이트(`js/notice-markup.js`)에서 한다. 서버는 공지에 관여하지 않는다.
- 종류 이름 → 동작은 코드의 대응표 한 곳에 모은다(예: 굵게·색은 `{ kind: 'style', className }`, 링크·이미지는 전용 처리). 굵게·색 같은 단순 스타일 종류를 새로 넣을 때는 대응표에 한 줄, CSS에 클래스 하나, 테스트를 더하면 되게 만든다.
- 버전: v2.6(사용자 확정).
